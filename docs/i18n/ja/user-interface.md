# ユーザーインターフェース

Insightは、ビジョンアプリケーションの検証を行う際に実行する開発タスクを中心に構成されており、ファイル検査、メディアの準備、ソースの起動、出力の確認、およびランタイムの健全性の監視などを行います。

## ワークスペース

ワークスペースビューでは、Insight で表示できるプロジェクトファイルを閲覧できます。Neat 開発環境では、通常これは`/workspace` です。SDK外では、Insight は現在の作業ディレクトリに戻ります。

ワークスペースを使って、次の操作を行います。

- ソースファイル、設定、モデル成果物、および生成された出力の検索と参照。
- プレビュー用のテキスト、コード、Markdown、画像、および選択されたバイナリファイルを表示します。
- MPKパッケージのアーカイブを、手動で展開することなく検査します。
- MLA統計、MPKマニフェスト、パイプラインシーケンスファイルなど、特定の開発成果物を確認できます。

ワークスペースは、アプリケーションが複数のビルド結果やログを生成する場合に特に役立ちます。ワークスペースを使用すると、同じ開発セッション内で、それらの成果物をブラウザからアクセスして確認できます。

![ Insight ワークスペースビュー。パイプラインのシーケンスグラフとワークスペースの成果物が表示されます。](../../images/insight-workspace-overview.png)

## メディアソース

メディアソースは、アプリケーションのテストに使用するメディアファイルを登録および管理する場所です。**メディアのインポート**を選択してインポートダイアログを開き、次の3つのソースから選択します。

- **ローカルファイル**: コンピューターから1つまたは複数のファイルを選択するか、ドラッグ＆ドロップしてください。H.264 MP4ファイルをアップロードすると、Bフレームを無効にして、低遅延再生のためにファイルが最適化され、元のフレームレートが維持されます。
- **カタログ**: SiMaが厳選したビデオカタログからビデオをインポートし、既知のアセットを使用した再現性のあるテストを実行できます。アセットの種類または名前で参照したり、カタログを検索したり、解像度、フレームレート、コーデックでフィルタリングしたり、ビデオをプレビューしたり、次に、1つのバリアントをインポートするか、複数の該当するアセットを選択してインポートします。
- **YouTube**: 通常のYouTube動画のURLを貼り付け、検証してプレビューを表示し、開始時間、クリップの長さ、および出力プロファイルを選択します。Insightは、`1080p30`、`720p30`、または`480p30`で、1分、3分、または5分のクリップをサポートします。インポートされたクリップは、Bフレームが無効になっているWebRTC互換のH.264に変換されます。ライブストリームはサポートされていません。通常の動画またはアーカイブされたライブストリームを使用してください。

カタログとYouTubeからのインポートにはネットワークアクセスが必要です。Insightは、メディアをダウンロードして準備する際に進捗状況を表示し、その結果をローカルメディアライブラリに保存します。

サポートされているビデオ形式には、`mp4`、`mov`、`avi`、`mkv`、および`webm`などの一般的なコンテナ形式が含まれます。Insightは、MJPEGアセットとHEVC/H.265メディアも認識し、コーデックを意識したストリーミングを可能にします。MJPEGおよびHEVCメディアは、元のコーデックの動作でストリーミングできるように保存されます。

メディアをインポートした後、ファイルリストをフィルタリングしたり、選択したファイルのプレビューを表示したり、基本的なメタデータを調べたり、不要になったファイルを削除したりできます。ストリーミングソースを構成する前に、メディアソースを使用して、どのファイルが利用可能か、Insightがどのコーデックを検出したか、およびそれらが読み取り可能かどうかを確認してください。

![Insight メディアソースの表示。選択した動画のプレビューとメディアメタデータが表示されます。](../../images/insight-media-library.png)

メディアソースは、インポート、ファイル選択、プレビュー、メタデータ検査、および削除アクションを1つのビューにまとめます。インポートされたカタログアセットは`catalog/`に、YouTubeクリップは`youtube/`に保存されるため、ファイルがどのようにライブラリに追加されたかを識別できます。

## ストリーミングのソース

「ストリーミングソース」ビューでは、アップロードされたメディアファイルをライブソーススロットに変換します。各ソーススロットは、RTSP URLを公開できます。

```text
rtsp://127.0.0.1:8554/src1
rtsp://127.0.0.1:8554/src2
rtsp://127.0.0.1:8554/src3
```

これらのURLは、Insightと同じSDKコンテナーで実行されているアプリケーションに対して正しいものです。アプリケーションがDevKitまたは別の外部マシンで実行されている場合は、SDKホストのIPアドレスと、`neat --json`からマッピングされた`rtsp.tcp`ホストポートを使用してください。

Insightは、割り当てられたメディアからコーデックとトランスポートオプションを選択します。

- H.264形式で、RTSPを介してH.264メディアストリームを送信します。
- H.265形式で、RTSPを介してHEVC/H.265メディアストリームを送信します。
- MJPEGメディアは、RTSPを通じてMJPEG形式で、またはHTTPを通じてmultipart MJPEG形式でストリーミングできます。

コーデックは選択されたメディアによって決定され、UIで手動で変更することはできません。RTSP経由のMJPEGは、RTP互換のMJPEGにエンコードされ、HTTP MJPEGは、カメラ形式のHTTPテストのためにMJPEGフレームを保持できます。

メディアをソースに割り当てたり、個々のソースを開始および停止したり、ソーススロット間で一意のファイルを自動的に割り当てたり、複数のソースをまとめて開始したり、すべてのストリームを停止したり、アプリケーションまたはテストハーネスで使用するためにストリームURLをコピーしたりできます。

このビューは、オブジェクト検出、セグメンテーション、トラッキング、分類、またはGenAIビジョンアプリケーションのために、再現可能な入力ストリームが必要な場合に役立ちます。

![ Insight ストリーミングソースビュー。割り当てられたソーススロットとソースプレビューが表示されます。](../../images/insight-rtsp-source.png)

ストリーミングソースビューでは、メディアファイルをソーススロットに割り当てたり、ストリームを開始または停止したり、アクティブなストリームURLをコピーしたり、アプリケーションに組み込む前に選択したソースをプレビューしたりできます。

## ビデオビューワー

ビデオビューワーには、ビデオ転送装置から送信される低遅延の WebRTC ストリームが表示されます。

チャンネル `N` について：

```text
video:    UDP 9000 + N
metadata: UDP 9100 + N
```

たとえば、チャンネル `0` は、ビデオ UDP `9000` とメタデータ UDP `9100` を使用します。チャンネル `1` は、ビデオ UDP `9001` とメタデータ UDP `9101` を使用します。

送信側が DevKit または別の外部マシンで実行されている場合は、`neat --json` からマッピングされた `videoUDP` および `metadataUDP` のホストポート範囲を使用します。チャンネル間の計算は同じですが、開始ポートが異なる場合があります。

ビューアーは、オブジェクト検出、分類、姿勢推定、セグメンテーション、トラッキングなど、一般的なビジョン出力のメタデータオーバーレイをレンダリングできます。ビューアーの設定を使用すると、信頼度しきい値、ROI表示、トラッキング履歴、同期バッファーなど、オーバーレイの動作を調整できます。メタデータのタイムスタンプは、ソースの PTS ミリ秒を使用し、利用できない場合は省略されます。

ビデオビューアーを使用して確認してください。

- アプリケーションは、指定されたチャンネルにビデオを送信しています。
- メタデータが、対応するメタデータチャンネルに送信されてきます。
- オーバーレイはビデオフレームに合わせて配置されます。
- ブラウザでの再生は正常です。

![ Insightビデオビューワーは、4つのチャンネルをグリッド形式で表示します。WebRTC ](../../images/insight-video-viewer.png)

ビデオビューワーは、一度に1つまたは複数のチャンネルを表示でき、ページネーションやチャンネル選択コントロールを備えており、大規模なマルチストリームテストに適しています。

## 周辺機器

周辺機器には、ボードに接続されたカメラと、各カメラが報告するモードが表示されます。検出はデバイス情報を読み取るだけで、ストリームを公開しません。そのため、スキャンが MIPI カメラ自体のモードを読み取る瞬間を除き、カメラはアプリケーションで引き続き使用できます。カメラエクスポート API も、ボードにアクセスせず、キャッシュされたスキャンから動作します。

### 選択したボード

Insight は、ヘッダーに表示される1台の選択済みボードを使用します。これを選択するとボード設定が開き、ボードの変更、接続のテスト、または再フラッシュされたボードのホストキーの信頼を行えます。周辺機器と統計はこの選択を使用します。

ボードは次の順序で選択されます。

- **入力したボード**：ボード設定を開き、アドレス、SSH ポート、およびユーザーを指定します。**デフォルトを使用**を選ぶと自動選択に戻ります。
- **ボードにインストールされた Insight**：Insight は実行中のボードを検査します。
- **Neat SDK**：`sima-cli sdk setup --devkit <ip>` でペアリングされた DevKit。

Insight は、実行アカウントのキーを使用して SSH 接続します。パスワードを要求または保存することはありません。認証に失敗すると、ボード上でキーを承認するための `ssh-copy-id` コマンドがページに表示されます。ボードを再フラッシュすると新しい SSH ホストキーが提示されます。Insight は、フィンガープリントを比較して **新しいキーを信頼** を選択するまで接続を拒否します。

### カメラとモード

**更新**を選択してボードをスキャンします。Insight は libcamera とメディアグラフを通じて MIPI カメラを、V4L2 を通じて USB カメラを検出します。各カメラについて、ID、接続、デバイス識別子、使用可能状態、およびカメラが報告するピクセル形式、解像度、フレームレートを表示します。各カメラとモードにはサポートレベルがあります。

| レベル | 意味 |
| --- | --- |
| 検証済み | このモードは Core `CameraInput` で検証されています。 |
| 報告済み | カメラはこのモードを報告しますが、Core では検証されていません。キャプチャ開始時に失敗する場合があります。 |
| 未サポート | Core `CameraInput` では使用できません。USB カメラ、RAW センサー形式、および NV12 以外の形式が含まれます。 |

MIPI カメラのモードを読み取るため、更新はストリーミングせずに libcamera でカメラを短時間開きます。別のアプリケーションが使用中のカメラはスキップされ、前回のスキャンのモードを保持します。使用可能状態にはカメラを保持しているプロセスが表示されます。Insight が他のユーザーのプロセスを確認できるのは、root として実行されている場合、またはボードでパスワードなしの `sudo` が許可されている場合のみで、それ以外は **不明** と報告されます。

### カメラ設定 API

ページでは、形式、解像度、およびフレームレートを確認できます。現在、コピーまたはダウンロード操作はありません。API クライアントは選択したモードを `/api/peripherals/cameras/export` に POST し、Python（`pyneat.CameraInputOptions`）、C++、および JSON 表現を受け取れます。リクエストには同じ `/api/peripherals` スナップショットの `generation` を含める必要があり、選択したボードが変更されていれば Insight は `409 stale_snapshot` を返します。Apps の `config.yaml` の `camera:` ブロックは、インストール済みの `libcamerasrc` が必要なキャプチャバッファーオプションをサポートする場合にのみ含まれます。エクスポートは常にカメラを明示的に指定します。USB カメラの場合、API は `CameraInput` 設定ではなくデバイス記述子を返します。

Modalix DevKit で測定された2つの動作がエクスポートに反映されます。厳密なゼロコピーでは起動しなかったため、CPU フォールバック（`allow_cpu_fallback = True`）を許可します。また、カメラは要求されたレートではなく、libcamera が選択したセンサーモードのフレームレートで配信します。1920×1080 の IMX477 は、15 fps または 30 fps を要求した場合でも約 66 fps を配信しました。より少ないフレームが必要な場合は、アプリケーションでフレームをドロップしてください。

## 統計

統計は、`simaai-sentinel` デーモンである Sentinel からボード自身のテレメトリを読み取るため、アプリケーションの動作とデバイスの動作を切り分けられます。ドロップしたフレームの原因はストリームパスにある場合もありますが、ボードの電力、ダイ上の温度、CPU 負荷、またはメモリの逼迫と相関している場合もあります。

統計は選択したボードで動作します。このボードは、周辺機器ページと同じ **ボード** パネルで選択します。

### Sentinel デーモン

そのボードで Sentinel が見つからない、停止している、または到達できない場合、ページは何よりも先にそのことを表示します。見つからない場合は **Sentinel をインストール** を選択します。Insight はボード自体で `sima-cli neat install sentinel` を実行します。これにはボード上の `sima-cli` とパスワードなしの `sudo` が必要です。どちらかがない場合、ページは代わりにボードのシェルで実行するコマンドを表示します。インストール済みで実行中のデーモンがここから再インストールされることはありません。インストーラーはデーモンを再起動するため、実行中のトレースが終了してしまうからです。

拒否または失敗したインストールは、読み取りの失敗ではなくインストールとして報告されます。ページはインストールが行われなかったことを示し、その理由をボード自身の文で示します（`sima-cli` がない、パスワードなしの `sudo` がない、インストーラーが 0 以外のコードで終了した、またはインストーラーは完了したがサービスが停止したままである）。インストーラーの出力は **インストーラーの出力** の下に保持されます。

### ライブメトリクス

DevKit ビューは、Sentinel 自身のターミナルダッシュボード（`simaai-sentinel ops`）と同様にレイアウトされています。ステータス行には、読み取り値がライブかどうかと、現在の Sentinel セッションの開始時刻が表示されます。セッションの平均とピークは、このセッションを対象とします。**CSV をエクスポート** は、Sentinel がセッションで保持している各サンプルのすべてのメトリクスをダウンロードします（直近 240 サンプル、約 8 分間。より長い期間が必要な場合は **実行** でトレースを記録してください）。**更新を一時停止** はポーリングを停止します。その下に 6 つのタブがあります。

- **概要**：最も高温の温度センサー、ボード電力、CPU 使用率、Linux メモリ、MLA メモリ、およびネットワークトラフィックのチャート。その下に **すべてのメトリクス** が折りたたまれており、すべてのメトリクスを Sentinel の順序で表示します。
- **温度**：最も高温のセンサーの推移と、各センサーグループ（MLA、APU、CVU、TOP、Board）の小さなチャート。
- **電力**：現在の電力、セッション平均、セッションピークの数値、セッション平均を示したウィンドウ全体のボード電力、および上端がボード合計になるよう積み上げた電源レール。
- **システム**：**CPU とメモリ** は、CPU 使用率、ロードアベレージ、Linux メモリ、MLA メモリ、および EV74 CMA の使用量をチャートで示します。**コア別 CPU** は負荷のヒートマップで、コアごとに 1 行、ウィンドウの 10 秒ごとに 1 列を単一の青色で表し、各コアの 1 分平均と最も負荷の高いコアを示します。平均がコアの制限を超えると、琥珀色または赤色に変わります。
- **ストレージとネットワーク**：eMMC の使用量、ネットワークの受信と送信、eMMC の読み取りと書き込み、およびそれらのメトリクス。
- **実行**：トレースを記録し、保存された実行を開く、比較する、または削除します。比較では、選択したすべての実行について 1 つの系列（総電力、温度の最大値、CPU、負荷、RAM、MLA メモリ、または EV74 CMA）を、すべての実行に共通する時間にわたり、実行に合わせたスケールで重ねて表示します。あわせて、各実行の最小値、平均値、中央値、P95、最大値、ベースラインに対する変化、およびエネルギーを表示します。メトリクスごとの比較はその下に折りたたまれています。

チャートは固定スケール（パーセンテージは 0-100、温度は 40-90 °C、その他はピークを上回る切りのよい数値まで）を使用し、Sentinel が定義する警告レベルと重大レベルを表示し、ホバーするとその時点のすべての系列の値を表示します。色はステータスを表します。チャートは、読み取り値が警告レベルまたは重大レベルを超えるまでは青色で、超えると琥珀色または赤色になります。タブ内のメトリクスがしきい値を超えると、タブ名にマークが付きます。ボードが測定できないメトリクスは、0 ではなくダッシュ（—）として表示されます。

チャートは、Sentinel が保持するウィンドウ全体である 240 サンプル（約 8 分間）をカバーします。ボードを初めて読み取るとき、および 1 分を超えてポーリングが一時停止した後には、Insight は Sentinel 自身のキャッシュからサンプルを取得し、その後はタブが開いていて表示されている間、2 秒ごとにサンプルを追加します。ブラウザーのタブが非表示になったときや、ビューを離れたときにもポーリングは停止します。

表示中にボードが応答しなくなった場合、ポーリングは停止しますが、パネルは残ります。ページを空にするのではなく、最後に読み取った値と、何が失敗したかについてのボード自身の説明を保持します。別のボードを選択する場合はこれとは異なります。その場合はまずすべてがクリアされるため、あるボードの数値が別のボードの名前で表示されることはありません。

### トレースと実行

トレースは、ワークロードの前後のすべてのサンプルを記録します。名前を付け、必要に応じてメモとタグを追加して、**トレースを開始** を選択します。**トレースを停止** を選択すると、トレースが実行としてボードに保存されます。Sentinel は一度に 1 つのトレースのみを記録し、保存済みの実行ですでに使用されている名前は拒否します。保存された実行は、状態、開始時刻、所要時間、その実行中に Sentinel が測定したエネルギー、およびサンプル数とともに一覧表示され、デーモンを再起動しても保持されます。実行を開くと、その概要が表示されます。記録されたすべてのメトリクスが、その時点で有効だったラベル、単位、グループ、しきい値、およびその実行のサンプル全体での最小値、最大値、平均値とともに表示されます。実行中のいずれかの時点で警告または重大のしきい値を超えたメトリクスにはマークが付きます。1 つのサンプルしか取得できなかった実行は、その時点から同じ時点までの範囲としてではなく、サンプルを取得した瞬間として報告され、その平均値、最小値、最大値は、すべてが等しい単一の値として示されます。実行のメタデータ（名前、メモ、サンプル間隔、Sentinel のバージョン、実行されたボード）はその下に表示されます。

実行にチェックを付けると、選択数と実行できる操作を示すツールバーが表示されます。2 から 8 個を選択して **比較** を選ぶと、メトリクスを行、実行を列とする表が表示されます。Sentinel は、1 つのベースライン実行を基準に比較を測定します。ベースラインは、各実行のメモとともにヘッダーに示されます。その他の各セルには、その実行におけるメトリクスの平均値が表示され、その横にベースラインに対する変化率が表示されます。表示できないほど小さな変化は、変化なしではなく “<0.01%” として表示されます。

セルに変化の代わりに “—” が表示されている場合、Sentinel が変化を提示しなかったことを意味します。表は、1 つのダッシュですべての理由を表すのではなく、どの理由に該当するかを示します。“—” にホバーする、Tab キーで移動する、またはタップすると、その横に理由が表示されます。スクリーンリーダーは、ダッシュとともに理由を読み上げます。理由は次のとおりです。

- **Sentinel はこの項目の変化を公開していません。** 実行の合計値（所要時間、エネルギー、サンプル数）は、パーセンテージなしで実行ごとに報告されます。
- **ベースラインの測定値は 0 であり、0 からの変化率はありません。** ベースラインはこのメトリクスを測定しています。単に 0 からのパーセンテージが存在しないだけです。これはアイドル状態のベースラインでのコア別 CPU 使用率でよく起こり、変化が最も大きくなることが多い箇所でもあります。ベースラインで平均 0%、他方の実行で 5.9% だったコアは、ここでは “—” と表示されるため、変化ではなく 2 つの値を読み取ってください。
- **ベースライン実行にはこのメトリクスの値がありません。** ベースラインがこのメトリクスをまったく測定しなかった唯一のケースです。
- **この実行にはこのメトリクスの値がありません。** 実行は一覧にあるものの Sentinel がその実行について何も集計しなかった場合、列全体がこの表示になり、そのことが表の上に明示されます。

実行の合計値は、ビューのほかの部分と同じ単位で表示されます。Sentinel がミリ秒で報告する所要時間は秒で、エネルギーはジュールで表示されます。

選択中の実行がボード上で削除されると、その行は一覧から消え、選択を解除するためのチェックボックスもなくなるため、すべての比較がその実行で失敗します。Insight は、Sentinel がもう一覧に含めていない選択済みの実行を名前で示し、選択から外すことを提案します。

比較では、実行を名前のカンマ区切りリスト 1 つとして要求するため、トレース名にカンマを含めることはできません。含めると、リクエストはボードに存在しない 2 つの実行として解釈され、誰も選択していない実行の名前を示して失敗します。Insight はトレースの開始時にそのような名前を拒否し、そのような名前を持つ保存済みの実行があれば、比較がその実行で失敗するのではなく、その実行を名前で示します。

### 切り替え前のボードの値

ボードの読み取りには SSH の往復が必要なため、別のボードを選択した後に応答が届くことがあります。別のボードを選択すると、前のボードから届く途中のものはすべてキャンセルされます。新しいボードはすぐに確認され、古いボードからの遅れた応答は、新しいボードの値として表示されずに破棄されます。**トレースを停止** は、そのトレースを読み取ったボードを名前で示し、別のボードのトレースを停止するのではなく拒否されます。選択したボードが別の場所（別のブラウザータブや API クライアント）で変更された場合、ページ上にすでに表示されている値には取得元のボードのラベルが付き、再読み込みする手段が表示されます。

### Insight ホスト

統計には **DevKit** と **ホスト** の 2 つのビューがあり、ここまでの説明はすべて DevKit ビューに関するものです。ホストビューは、Insight 自体が実行されているマシン（SDK コンテナー、または Insight がインストールされているボード）について、`/api/metrics` から CPU 負荷、メモリ、ディスク、およびプラットフォームが公開している場合は温度を報告します。コンテナーのディスクが不足していないかなど、DevKit ビューとは異なる疑問に答えるもので、読み取り間隔は 2 秒ではなく 15 秒です。従来の `REMOTE_DEVKIT` 設定が指定されている場合、このパネルは代わりにその接続について報告し、その旨を表示します。エンドポイントが読み取り値をまったく返さない場合、パネルはラベルをダッシュとともに並べるのではなく、その旨を表示します。

### NEAT プロファイリングタイムライン

ホストビューの Insight ホストパネルの下にあるプロファイリングタイムラインは、実行中のアプリケーションから Insight がストリーミングするプロファイリングイベントの数値フィールドをプロットします。これは Sentinel から独立しており、デバイスではなくアプリケーションを測定します。

## システム情報

システム情報パネルには、Insight が認識できる環境の概要が表示されます。Neat 開発環境では、SDK とコンポーネントの情報、Insight のステータス、更新情報、および `mainUI` や `videoUI` などの公開ポートマッピングが表示されます。

URL がデフォルトポートと一致しない場合に最初に確認すべき場所です。Insight は、利用可能なポートマップを読み取り、ビューアーを開く際にマッピングされた `videoUI` ポートを使用します。コマンドラインワークフローの場合、`neat --json` は同じポートマップ情報を表示します。
