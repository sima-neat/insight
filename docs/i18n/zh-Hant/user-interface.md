# 使用者介面

Insight 是圍繞您在驗證視覺應用程式時執行的開發工作來組織的：檢查檔案、準備媒體、啟動來源、檢視輸出，以及監看執行階段的健康狀態。

## 工作區

「工作區」檢視可讓您瀏覽 Insight 可見的專案檔案。在 Neat 開發環境中，這通常是 `/workspace`；在 SDK 之外，Insight 會退而使用目前的工作目錄。

使用「工作區」來：

- 搜尋並瀏覽原始碼檔案、設定、模型成品與產生的輸出。
- 預覽文字、程式碼、Markdown、影像，以及特定的二進位成品。
- 無須手動解壓縮即可檢查 MPK 套件封存檔。
- 檢視專門的開發成品，例如 MLA 統計資料、MPK 資訊清單與管線序列檔案。

當應用程式產生多個建置輸出與日誌時，「工作區」特別有用。它提供一種可透過瀏覽器存取的方式，讓您在同一個開發工作階段中檢查這些成品。

![Insight 工作區檢視，顯示管線序列圖與工作區成品。](../../images/insight-workspace-overview.png)

## 媒體來源

「媒體來源」是您新增與管理應用程式測試所用媒體檔案的地方。選取 **Import Media**（匯入媒體）以開啟匯入對話方塊，然後從三種來源中擇一：

- **Local files**（本機檔案）：從電腦選擇或拖放一個或多個檔案。上傳的 H.264 MP4 會經過正規化以進行低延遲播放，並停用 B 影格，同時保留來源影格率。
- **Catalog**（目錄）：從 SiMa 精選的影片目錄匯入，以已知的素材進行可重複的測試。可依素材類型或名稱瀏覽、搜尋目錄、依解析度、影格率與編解碼器篩選、預覽影片，然後匯入一個變體，或選取並匯入多個符合條件的素材。
- **YouTube**：貼上一般的 YouTube 影片 URL，驗證後即可顯示預覽，並選擇開始時間、片段長度與輸出設定檔。Insight 支援 1、3 或 5 分鐘的片段，規格為 `1080p30`、`720p30` 或 `480p30`。匯入的片段會轉換為適合 WebRTC 的 H.264，並停用 B 影格。不支援進行中的直播；請使用一般影片或已封存的直播。

從目錄與 YouTube 匯入需要網路存取。Insight 會在下載與準備媒體時顯示進度，然後將結果儲存到本機媒體庫。

支援的影片格式包括常見的容器格式，例如 `mp4`、`mov`、`avi`、`mkv` 與 `webm`。Insight 也能辨識 MJPEG 素材與 HEVC/H.265 媒體，以進行能感知編解碼器的串流。MJPEG 與 HEVC 媒體會被保留，以便以其原始編解碼器行為進行串流。

匯入媒體後，您可以篩選檔案清單、預覽選取的檔案、檢查其基本中繼資料，或刪除不再需要的檔案。請在設定串流來源之前使用「媒體來源」，以便了解有哪些檔案可用、Insight 偵測到哪種編解碼器，以及這些檔案是否可讀取。

![Insight 媒體來源檢視，顯示選取的影片預覽與媒體中繼資料。](../../images/insight-media-library.png)

「媒體來源」在單一檢視中結合了匯入、檔案選取、預覽、中繼資料檢查與刪除動作。匯入的目錄素材會儲存在 `catalog/` 下，YouTube 片段則儲存在 `youtube/` 下，讓您能辨識檔案是如何進入媒體庫的。

## 串流來源

「串流來源」檢視會將上傳的媒體檔案轉換為即時來源槽位。每個來源槽位都可以公開一個 RTSP URL：

```text
rtsp://127.0.0.1:8554/src1
rtsp://127.0.0.1:8554/src2
rtsp://127.0.0.1:8554/src3
```

這些 URL 適用於與 Insight 在同一個 SDK 容器中執行的應用程式。若應用程式在 DevKit 或其他外部機器上執行，請使用 SDK 主機的 IP 位址，以及 `neat --json` 中對應的 `rtsp.tcp` 主機連接埠。

Insight 會依據指派的媒體選擇編解碼器與傳輸選項：

- H.264 媒體透過 RTSP 以 H.264 串流。
- HEVC/H.265 媒體透過 RTSP 以 H.265 串流。
- MJPEG 媒體可透過 RTSP 以 MJPEG 串流，或透過 HTTP 以 multipart MJPEG 串流。

編解碼器由所選的媒體決定，無法在 UI 中手動變更。透過 RTSP 傳送的 MJPEG 會編碼為相容於 RTP 的 MJPEG，而 HTTP MJPEG 則可保留 MJPEG 影格，以進行類似攝影機的 HTTP 測試。

您可以將媒體指派給來源、個別啟動與停止來源、將不重複的檔案自動指派到各來源槽位、批次啟動來源、停止所有串流，以及複製串流 URL 供應用程式或測試框架使用。

當您需要為物件偵測、分割、追蹤、分類或 GenAI 視覺應用程式提供可重複的輸入串流時，這個檢視很有用。

![Insight 串流來源檢視，顯示已指派的來源槽位與來源預覽。](../../images/insight-rtsp-source.png)

「串流來源」檢視可讓您將媒體檔案指派給來源槽位、啟動或停止串流、複製作用中的串流 URL，並在將所選來源接入應用程式之前先行預覽。

### 使用網路攝影機作為來源

連接到執行瀏覽器之電腦的網路攝影機可以作為即時來源，讓您無須先將檔案複製到開發板，就能以真實相機測試應用程式。

1. 前往「媒體來源」，在 **Local cameras**（本機相機）下選取 **Enable camera access**（啟用相機存取）。瀏覽器會要求相機權限；Insight 無法代您授予。
2. 允許存取後，您的相機會出現在每個來源下拉選單的 **Cameras**（相機）群組中，位於影片檔案上方：

   ```text
   Not assigned
   Cameras
     Integrated Camera
     USB Camera
   Video files
     catalog/parking_garage_cars/parking_garage_cars_1080p.mp4
   ```

3. 為來源槽位選取相機，然後選取 **Start**（啟動）。該列會顯示 `[CAM]` 標記（影片檔案顯示 `[VID]`），瀏覽器會將相機發布到 Insight，而槽位會回報 `Live`。
4. 使用 **Copy URL**（複製 URL）取得 RTSP URL，並將應用程式指向它，做法與檔案來源完全相同。

相機清單會隨相機的連接與中斷而更新。網路攝影機來源只發布視訊，格式為 H.264。

擷取進行中時，來源清單旁的預覽會顯示您的本機相機畫面。這不是開發板接收到的視訊，也不會呈現接收端應用程式所看到的延遲；若發布失敗，擷取會停止並清除預覽。

選取 **Stop**（停止）、拔除相機或關閉瀏覽器分頁都會結束串流，並將槽位恢復為 `Idle`。**Stop All**（全部停止）、**Reset**（重設）與 **Auto Assign**（自動指派）也會釋放所有網路攝影機，因為它們都會收回那些槽位：Reset 與 Auto Assign 也會清除相機選擇，因此之後請重新選取相機。網路攝影機發布期間，瀏覽器分頁必須保持開啟：它就是將視訊傳送到 Insight 的元件。基於同樣的原因，Insight 重新啟動後，網路攝影機來源絕不會恢復為 `Live`——請重新選取相機並再次啟動。

若啟動網路攝影機失敗，訊息會指出原因：

| 您看到的訊息 | 處理方式 |
| --- | --- |
| 相機權限遭拒（Camera permission was denied） | 在瀏覽器設定中允許 Insight 網站存取相機，然後在「媒體來源」→ Local cameras（本機相機）下重新啟用相機存取。 |
| 該相機已無法使用（That camera is no longer available） | 相機已中斷連接。選取 **Refresh cameras**（重新整理相機）並重新選取它。 |
| 無法啟動相機（The camera could not be started） | 另一個應用程式正在使用相機。請關閉該應用程式後重試。 |
| 無法連線到網路攝影機發布端點（Could not reach the webcam publish endpoint） | 瀏覽器無法連線到發布接聽程式。請信任 `webrtcWhip` 端點的憑證（開啟其 URL 一次以接受憑證），並確認連接埠可連線（請參閱 [連接埠與網路行為](ports-network.md)）。 |
| 網路攝影機發布遭拒（Webcam publish was rejected） | Insight 無法接受該串流。請確認 `webrtcWhip` 連接埠可連線（請參閱 [連接埠與網路行為](ports-network.md)），且您的瀏覽器信任 Insight 憑證。 |

瀏覽器只允許在其視為安全的頁面上存取相機。若 **Enable camera access**（啟用相機存取）沒有任何反應，請先透過 HTTPS 開啟 Insight 並信任其憑證；請參閱 [安裝與升級](install-upgrade.md)。

## 視訊檢視器

視訊檢視器會顯示來自視訊轉送器的低延遲 WebRTC 串流。

對於頻道 `N`：

```text
video:    UDP 9000 + N
metadata: UDP 9100 + N
```

例如，頻道 `0` 使用視訊 UDP `9000` 與中繼資料 UDP `9100`；頻道 `1` 使用視訊 UDP `9001` 與中繼資料 UDP `9101`。

若傳送端在 DevKit 或其他外部機器上執行，請使用 `neat --json` 中對應的 `videoUDP` 與 `metadataUDP` 主機連接埠範圍。頻道的計算方式相同，但起始連接埠可能不同。

檢視器可以呈現常用視覺輸出（包括物件偵測、分類、姿勢估計、分割和追蹤）的中繼資料疊加層。每個中繼資料類型都有 **Show Overlay** 開關，可在不變更信賴度閾值或樣式的情況下隱藏輸出。姿勢估計也可分別顯示關節標記和地標名稱。與影格相關聯的資料也可顯示在每個頻道的獨立輔助面板中；第一個內建呈現器是 BlazePose 3D。多個輔助檢視會顯示為分頁，面板可以收合、展開或隱藏。通訊協定請參閱[輔助視覺化](auxiliary-visualizations.md)。檢視器設定可調整信賴度閾值、ROI 顯示、追蹤歷史記錄和同步緩衝。中繼資料時間戳使用來源 PTS 毫秒，如果無法使用則會省略。

使用視訊檢視器確認：

- 應用程式正在將影片傳送到預期的頻道。
- 中繼資料即將傳送到對應的中繼資料通道。
- 疊圖會與影片畫面對齊。
- 輔助檢視會隨對應的影片影格清除並更新。
- 瀏覽器播放功能運作正常。

![Insight 視訊檢視器，顯示四頻道 WebRTC 網格。](../../images/insight-video-viewer.png)

視訊檢視器一次可以顯示一個或多個頻道，並提供分頁與頻道選擇控制項，以進行較大規模的多串流測試。

## 周邊裝置

Peripherals（周邊裝置）會列出連接到開發板的相機與麥克風，並顯示每個裝置回報的內容。由開發板上的 SiMa Sentinel 探索這些裝置；Insight 讀取 Sentinel 的目錄。探索只會讀取裝置資訊：它絕不會開啟裝置或從裝置串流，因此裝置仍可供您的應用程式使用。只有相機預覽與麥克風測試會開啟裝置，而且只在其執行期間。

### 選取的開發板

Insight 會使用一個選取的開發板，顯示於頁首。選取它即可開啟開發板設定，您可以在其中變更開發板、測試連線，或信任重新燒錄之開發板的主機金鑰。「周邊裝置」與「統計資料」都會使用此選擇。

開發板依下列順序選定：

- **您輸入的開發板**：開啟開發板設定，並提供其位址、SSH 連接埠與使用者。**Use default**（使用預設值）會回到自動選擇。
- **安裝在開發板上的 Insight**：Insight 會檢查其所執行的開發板。
- **Neat SDK**：以 `sima-cli sdk setup --devkit <ip>` 配對的 DevKit。

Insight 會使用執行它之帳戶的金鑰透過 SSH 連線。它絕不會要求或儲存密碼。若驗證失敗，頁面會顯示可在開發板上授權金鑰的 `ssh-copy-id` 指令。開發板重新燒錄後會出示新的 SSH 主機金鑰；在您比對指紋並選取 **Trust new key**（信任新金鑰）之前，Insight 會拒絕連線。

### 相機與模式

選取 **Refresh**（重新整理）以掃描開發板：Insight 會要求 SiMa Sentinel 重新掃描並等待結果。Sentinel 會透過媒體圖與 ISP 找到 MIPI 相機，並透過 V4L2 找到 USB 相機。若 Sentinel 未安裝、未執行，或版本過舊而無法回報周邊裝置，頁面會說明這一點；請使用 `sima-cli neat install sentinel` 安裝或更新。對於每部相機，頁面會顯示其身分、連線、裝置識別碼，以及相機回報的像素格式與解析度。任何相機的解析度都不會顯示影格率：MIPI 相機的影格率取決於其正在執行的感測器模式，在相機執行前無從得知，因此頁面以相同方式對待所有相機。Insight 不會設定影格率。每個模式處於下列三種狀態之一，像素格式與解析度選單會依狀態將其項目分組：

| 狀態 | 意義 |
| --- | --- |
| Available（可用） | 開發板的相機 overlay 支援該相機的感測器、ISP 能輸出此模式的尺寸，且其像素格式為 NV12。 |
| Unverified（未驗證） | 在 ISP 於執行階段採用感測器尺寸的開發板（Platform 3.0）上，受支援感測器的某個 NV12 尺寸，而 SiMa Sentinel 無法確認 libcamera 會精確地以該尺寸串流，因為 libcamera 可能從較大的模式裁切出它。可選取並預覽以進行確認；但絕不會被預先選取。 |
| Unsupported（不支援） | 上述任一條件不成立。USB 相機在開發板上沒有相機 overlay，因此一律為 Unsupported（不支援），頁面不會為其顯示原因。MIPI 相機的原因會指出是哪一項：感測器不在開發板的相機 overlay 中；ISP 無法輸出該尺寸；格式不是 NV12；或在 ISP 於執行階段採用感測器尺寸的開發板（Platform 3.0）上，尺寸寬於 libcamera 串流的寬度（IMX477 為 4032 像素）。若 Sentinel 版本過舊而無法回報開發板的相機 overlay，則在您更新之前，每個模式都會是 Unsupported（不支援）。 |

每個模式的狀態由 SiMa Sentinel 判定並附上原因；Insight 顯示該結果。若 Sentinel 版本過舊而無法判定，Insight 會對 Sentinel 的目錄套用相同的規則。overlay 檢查會將 Sentinel 在開發板裝置樹中連結到該相機的感測器，與安裝在 `/boot` 下的 overlay 所支援的感測器進行比對。NV12 條件是關於 Neat 的 `CameraInput` 的固定事實，它輸出 NV12；Insight 不會查詢開發板上的 Neat。每部偵測到的相機都會顯示 **Connected**（已連線）標籤及其狀態：只要有任一模式為 Available（可用）即為 **Available**，否則只要有任一模式為 Unverified（未驗證）即為 **Unverified**（未驗證），否則為 **Unsupported**（不支援）；Unverified 或 Unsupported 相機的面板會說明原因。Insight 不會指出是否有其他程式正在使用相機。

### 預覽相機

選取 **Start preview**（開始預覽）即可看到相機所拍攝的畫面。Insight 會透過與開發板的現有連線，在開發板上執行 GStreamer 管線：它會擷取所選的模式（MIPI 相機使用 `libcamerasrc`，USB 相機使用 `v4l2src`），將其縮放至寬度最多 640 像素、最高 15 fps，並傳回 JPEG 影格，頁面會在影格抵達時加以顯示。除了 GStreamer 本身之外，開發板上不需要其他任何元件；若缺少 `gst-launch-1.0`，預覽會指出需要安裝的套件（`gstreamer1.0-tools`、`gstreamer1.0-plugins-base`、`gstreamer1.0-plugins-good`，MIPI 相機另需 `gstreamer1.0-libcamera`）。

預覽會佔用相機，因此在您停止預覽之前，您的應用程式無法開啟該相機。Insight 不會在已被其他程序使用的相機上啟動預覽，也絕不會替您停止該程序。當您選取 **Stop**（停止）、離開頁面、重新整理掃描或變更選取的開發板時，擷取就會停止。關閉瀏覽器也會停止擷取。若 Insight 停止或重新啟動，開發板上的管線會在其輸出連線關閉後，於下一個影格時結束；若網路在沒有任何提示的情況下中斷，管線可能會持續佔用相機，直到開發板的 SSH 連線逾時為止。若要清除仍佔用相機的預覽，請在頁面仍顯示該預覽時選取 **Stop**（停止）、等待該逾時，或結束開發板上的 `gst-launch-1.0` 程序。

MIPI 相機可預覽其 Available（可用）與 Unverified（未驗證）模式。在 ISP 於執行階段採用感測器尺寸的開發板（Platform 3.0）上，感測器列出的尺寸仍可能不是 libcamera 會輸出的尺寸；此時預覽會指出 libcamera 實際串流的尺寸，供您選擇。USB 相機可預覽它以 MJPG 或原始格式（例如 YUYV）列出的任何模式，即使其模式對 Neat 的 `CameraInput` 而言是 Unsupported（不支援）；當開發板具有穩定的 `/dev/v4l/by-id` 路徑時，Insight 會透過該路徑開啟相機。

預覽執行時，其旁的模式會顯示相機的影格率，此影格率可能高於預覽的 15 fps。預覽會向相機要求所選模式的影格率。對於 USB 相機，顯示的是該模式的影格率。對於 MIPI 相機，顯示的是感測器在此模式下能提供的最高影格率，標示為「up to」（最高），Insight 會在第一個影格抵達後向 SiMa Sentinel 取得此值，因此會在畫面出現數秒後才顯示；若 Sentinel 無法回報，則不會顯示影格率。

### Camera setup（相機設定）

讀取開發板裝置樹的 Sentinel 也會回報開發板針對相機的設定方式。執行 Refresh（重新整理）後，開發板設定會顯示開發板的 **Model**（型號），以及一行 **Camera setup**（相機設定），列出開發板所載入、用於設定相機感測器的 overlay。若使用較舊的 Sentinel，則不會顯示這些詳細資料。

### 麥克風

重新整理也會列出 SiMa Sentinel 回報的每個 ALSA 擷取裝置，無論是 USB 或板載裝置。對於每個麥克風，Insight 會顯示其名稱、用來開啟它的 ALSA 裝置名稱（例如 `hw:CARD=Nano,DEV=0`），以及（對於 USB 音訊裝置）它可擷取的取樣格式、聲道數、位元深度與取樣率。板載音效卡不會回報這些資訊，頁面會說明這一點。

探索絕不會開啟音效裝置：Sentinel 會讀取 `/proc/asound` 與 sysfs。USB 麥克風拔除後再插回同一個連接埠時，會保持相同的身分，即使其音效卡編號改變亦然；插到其他連接埠時，則視為不同的麥克風。

若要聆聽麥克風，請選取 **Test microphone**（測試麥克風）並說話；音量表會顯示麥克風收到的聲音。完成後選取 **Stop recording**（停止錄音）（測試會在 30 秒後自行停止），Insight 會在頁面中播放錄音。**Stop playing**（停止播放）會結束播放。若錄音一直低於約 -60 dBFS，頁面會說明未收到任何聲音；請檢查麥克風的靜音按鈕與增益。只有測試會開啟裝置，而且只在錄音期間開啟。錄音前，Insight 會重新讀取 Sentinel 的目錄，並只從 Sentinel 指定的裝置錄音；若自上次掃描以來開發板的裝置有所變更，頁面會要求您先重新整理。若另一個應用程式已開啟麥克風，測試會遭拒，且不會干擾該應用程式。Insight 不會設定音訊輸入：Core 沒有音訊輸入。

## 統計資料

「統計資料」會從 Sentinel（`simaai-sentinel` 常駐程式）讀取開發板本身的遙測資料，讓您能將應用程式行為與裝置行為區分開來。掉格可能來自串流路徑，但也可能與開發板功耗、晶片溫度、CPU 負載或記憶體壓力相關。

「統計資料」作用於選取的開發板，此開發板是在「周邊裝置」頁面所使用的同一個 **Board**（開發板）面板中選定。

### Sentinel 常駐程式

頁面會先回報 Sentinel 是否已安裝並在該開發板上執行，以及其版本。若未安裝，請選取 **Install Sentinel**（安裝 Sentinel）：Insight 會直接在開發板上執行 `sima-cli neat install sentinel`，這需要開發板上有 `sima-cli` 以及無密碼 `sudo`。若缺少其中任一項，頁面會改為列出應在開發板 shell 中執行的指令。已安裝且正在執行的常駐程式絕不會從此處重新安裝，因為安裝程式會重新啟動它，進而中斷進行中的追蹤。

遭拒或失敗的安裝會以安裝結果回報，而不是當作讀取失敗：頁面會說明安裝並未完成，並提供開發板本身說明原因的句子——沒有 `sima-cli`、沒有無密碼 `sudo`、安裝程式以非零值結束，或安裝完成後服務仍未啟動——並將安裝程式的輸出收在 **Installer output**（安裝程式輸出）之下。

### 即時指標

DevKit 檢視的版面與 Sentinel 本身的終端機儀表板（`simaai-sentinel ops`）相同。狀態列會顯示讀數是否為即時，以及目前的 Sentinel 工作階段何時開始，也就是工作階段平均值與峰值所涵蓋的範圍。**Export CSV**（匯出 CSV）會下載 Sentinel 為此工作階段保留之每個樣本的所有指標（最近 240 個，約八分鐘；若需要更長時間，請在 **Runs**（執行記錄）下錄製追蹤），而 **Pause updates**（暫停更新）會停止輪詢。其下方有六個分頁：

- **Overview**（概覽）：最熱溫度感測器、開發板功耗、CPU 使用率、Linux 記憶體、MLA 記憶體與網路流量的圖表，下方收合著 **All metrics**（所有指標），依 Sentinel 的順序列出每個指標。
- **Thermal**（溫度）：最熱感測器隨時間的變化，接著以小型圖表呈現各感測器群組（MLA、APU、CVU、TOP、Board）。
- **Power**（功耗）：以數字呈現目前、工作階段平均與工作階段峰值功耗；呈現時間窗內的開發板功耗並標示工作階段平均值；以及堆疊的電源軌，讓頂端邊緣即為開發板總功耗。
- **System**（系統）：**CPU & memory**（CPU 與記憶體）以圖表呈現 CPU 使用率、平均負載、Linux 記憶體、MLA 記憶體與 EV74 CMA 使用量。**Per-core CPU**（各核心 CPU）是負載熱圖，每個核心一列、時間窗中每 10 秒一欄，使用單一藍色，並附上每個核心的一分鐘平均值與最忙碌的核心；平均值超出核心的限制時會轉為琥珀色或紅色。
- **Storage & Network**（儲存與網路）：eMMC 使用量、網路接收與傳送、eMMC 讀取與寫入，以及其指標。
- **Runs**（執行記錄）：錄製追蹤，以及開啟、比較或刪除已儲存的執行記錄。比較功能會針對每筆選取的執行記錄，在它們共同涵蓋的時間範圍內疊加一個序列（總功耗、溫度最大值、CPU、負載、RAM、MLA 記憶體或 EV74 CMA），並採用符合這些執行記錄的刻度，同時列出每筆執行記錄的最小值、平均值、中位數、P95、最大值、相對於基準的變化，以及能量；逐指標的比較則收合在其下方。

圖表使用固定刻度（百分比 0-100、溫度 40-90 °C，其他項目則上限為高於其峰值的整數），顯示 Sentinel 定義的警告與嚴重層級，並在您將游標停留時讀出該時間點的每個序列。顏色代表狀態：圖表在讀數超過警告或嚴重層級前為藍色，之後轉為琥珀色或紅色。當分頁中有指標超過門檻時，該分頁名稱會被標示。開發板無法量測的指標會顯示為破折號，絕不顯示為零。

圖表涵蓋 Sentinel 保留的整個時間窗，即 240 個樣本（約八分鐘）：第一次讀取開發板時，以及輪詢暫停超過一分鐘後，Insight 會從 Sentinel 本身的快取取得這些樣本，然後在分頁開啟且可見時每兩秒新增一個樣本。當瀏覽器分頁被隱藏或離開此檢視時，輪詢也會停止。

若開發板在您檢視時停止回應，輪詢會停止，但面板會保留，顯示最後讀取的值以及開發板本身對失敗原因的說明，而不會清空頁面。選取不同的開發板則是另一回事：這會先清除所有內容，因此絕不會在另一個開發板的名稱下顯示某個開發板的數值。

### 追蹤與執行記錄

追蹤會記錄某個工作負載期間的每個樣本。為其命名，可選擇加入備註與標籤，然後選取 **Start trace**（開始追蹤）；**Stop trace**（停止追蹤）會將其儲存為開發板上的一筆執行記錄。Sentinel 一次只記錄一個追蹤，並會拒絕已儲存執行記錄已使用的名稱。已儲存的執行記錄會列出其狀態、開始時間、持續時間、Sentinel 在該執行期間量測到的能量，以及樣本數，且在常駐程式重新啟動後仍會保留。開啟執行記錄即可查看其摘要：它記錄的每個指標，連同當時生效的標籤、單位、群組與門檻，以及該執行記錄各樣本中的最小值、最大值與平均值。在執行期間任一時間點超過警告或嚴重門檻的指標會被標示。只擷取到一個樣本的執行記錄會以該樣本的時間點呈現，而不是從該時間點到其本身的範圍，且其平均值、最小值與最大值會標示為同一個單一值。執行記錄的中繼資料（名稱、備註、取樣間隔、Sentinel 版本，以及執行所在的開發板）位於其下方。

勾選執行記錄時會顯示工具列，列出已選取的數量以及可對其執行的動作。選取二至八筆並選取 **Compare**（比較），即可將指標排成列、執行記錄排成欄。Sentinel 會以一筆基準執行記錄來衡量比較結果，該基準會連同每筆執行記錄的備註一起標示在標頭中；其他每個儲存格都會顯示該指標在該執行中的平均值，旁邊附上相對於基準的百分比變化。小到無法顯示的變化會顯示為「<0.01%」，而不是顯示為完全沒有變化。

當儲存格以「—」取代變化值時，表示 Sentinel 未提供變化值，而表格會說明適用的是哪一個原因，而不是讓同一個破折號代表所有原因。將游標停留、以 Tab 鍵移至或點按「—」，即可在旁邊看到原因；螢幕閱讀器會連同破折號一起讀出原因。原因如下：

- **Sentinel 不會為其發布變化值。** 執行總計（持續時間、能量與樣本數）會按每筆執行記錄回報，不附百分比。
- **基準量測值為 0，而從 0 開始無法計算百分比變化。** 基準確實量測了該指標；只是無法從零計算百分比。這在閒置基準的各核心 CPU 使用率中很常見，而這也往往是變化最大的地方：某個核心在基準中平均為 0%、在另一筆執行記錄中為 5.9%，此處會顯示「—」，因此請比較兩個值，而不是看變化值。
- **基準執行記錄沒有該指標的值。** 這是基準從未量測該指標的唯一情況。
- **此執行記錄沒有該指標的值。** 若某筆執行記錄有列出，但 Sentinel 沒有為其產生任何摘要，則整欄都會如此顯示，並在表格上方特別註明。

執行總計會以此檢視其他部分所用的單位顯示：Sentinel 以毫秒回報的持續時間會以秒顯示，能量則以焦耳顯示。

若某筆執行記錄在選取狀態下於開發板上被刪除，它的列會從清單中消失，也就不再有可用來取消選取的核取方塊，因此每次比較都會因它而失敗。Insight 會指出 Sentinel 已不再列出的任何已選取執行記錄，並提供將其從選取中移除的選項。

開啟與比較執行記錄有大小上限。Insight 最多從開發板讀取 12 MiB 的 Sentinel 回應，而已儲存的執行記錄會包含其記錄的每個樣本，每兩秒一個。長度超過約三小時的執行記錄無法開啟，長度合計超過約三小時的多筆執行記錄也無法一起比較。此時 Insight 會說明回應過大而無法讀取。對於想要開啟或比較的執行記錄，請錄製較短的追蹤。

比較會以一份逗號分隔的名稱清單要求其執行記錄，因此追蹤名稱不能包含逗號：該要求會被解讀為開發板上不存在的兩筆執行記錄，並以一筆沒有人選取的執行記錄名稱失敗。Insight 會在您開始追蹤時拒絕這類名稱，並指出任何名稱中帶有逗號的已儲存執行記錄，而不是讓 Compare（比較）因它而失敗。

### 來自您已離開之開發板的值

讀取開發板需要一次 SSH 往返，因此回應可能會在您選取另一個開發板之後才抵達。選取新的開發板會取消所有仍在從前一個開發板傳來途中的內容：新的開發板會立即接受檢查，而來自舊開發板的延遲回應會被捨棄，不會顯示為新開發板的值。**Stop trace**（停止追蹤）會指出其追蹤是從哪個開發板讀取的，並會遭拒，而不會停止另一個開發板上的追蹤。當選取的開發板在其他地方（另一個瀏覽器分頁或 API 客戶端）被變更時，頁面上既有的值會標示其來源開發板，並提供重新讀取的方式。

### Insight 主機

在執行記錄下方，一個精簡面板會從 `/api/metrics` 回報 Insight 本身所執行的機器（SDK 容器，或安裝了 Insight 的開發板）：CPU 負載、記憶體、磁碟，以及平台有提供時的溫度。它回答的問題與上方的開發板遙測不同，例如容器是否即將耗盡磁碟空間，而且每 15 秒讀取一次，而不是每兩秒。設定舊版 `REMOTE_DEVKIT` 組態時，此面板會改為回報該連線，並註明這一點。當端點回應中完全沒有讀數時，面板會直接說明，而不是列出各標籤並在旁顯示破折號。

### NEAT 效能分析時間軸

此分頁最後是效能分析時間軸，它會繪製 Insight 從執行中應用程式串流而來的效能分析事件中的數值欄位。它與 Sentinel 無關：它量測的是應用程式，而不是裝置。

## 系統資訊

系統資訊面板會摘要 Insight 可見的環境。在 Neat 開發環境中，它可以顯示 SDK 與元件資訊、Insight 狀態、更新資訊，以及公開的連接埠對應，例如 `mainUI` 與 `videoUI`。

當 URL 與預設連接埠不符時，這是第一個應該檢查的地方。Insight 會讀取可用的連接埠對應，並在開啟檢視器時使用對應的 `videoUI` 連接埠。對於命令列工作流程，`neat --json` 會顯示相同的連接埠對應資訊。
