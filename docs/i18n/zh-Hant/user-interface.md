# 使用者介面

Insight 的設計是以您在驗證視覺應用程式時所執行的開發任務為中心：檢查檔案、準備媒體、啟動來源、檢視輸出，以及監控執行階段的狀態。

## 工作區

「工作區」檢視可讓您瀏覽對 Insight 可見的專案檔案。在 Neat 開發環境中，這通常是 `/workspace`；在 SDK 之外，Insight 會切換到目前的本機目錄。

使用「工作區」來：

- 搜尋和瀏覽原始檔案、設定、模型成品以及產生的輸出結果。
- 預覽文字、程式碼、Markdown 格式、圖片，以及選取的二進位檔案。
- 無需手動解壓縮，即可檢查 MPK 套件檔案。
- 檢視專用開發構件，例如 MLA 統計資料、MPK 資訊檔和流程序列檔案。

工作區在應用程式產生多個建置輸出和日誌時特別有用。它提供一種可透過瀏覽器存取的檢視方式，讓您可以在相同的開發階段中檢查這些構件。

## 媒體來源

「媒體來源」是您新增和管理用於應用程式測試的媒體檔案的地方。選取「匯入媒體」以開啟匯入對話方塊，然後選擇以下三種來源之一：

- **本機檔案**：選擇或將一個或多個檔案從您的電腦拖曳到此處。上傳的 H.264 MP4 檔案會經過處理，以實現低延遲播放，同時停用 B 幀，但保留原始幀率。
- **目錄**：從 SiMa 整理的影片目錄中匯入，以便進行可重複的測試，並使用已知的素材。您可以按素材類型或名稱瀏覽，搜尋目錄，按解析度、幀率和編碼器進行篩選，預覽影片，然後匯入一個變體，或選擇並匯入多個符合條件的素材。
- **YouTube：**貼上一般的 YouTube 影片網址，驗證後即可顯示預覽，然後選擇開始時間、片段長度和輸出設定。Insight 支援 1 分鐘、3 分鐘或 5 分鐘的片段，解析度為 `1080p30`、`720p30` 或 `480p30`。匯入的片段會轉換為適合 WebRTC 的 H.264 格式，並停用 B 幀。目前不支援即時直播；請使用一般影片或已儲存的直播影片。

從目錄和 YouTube 匯入需要網路連線。Insight 會在下載和準備媒體時顯示進度，然後將結果儲存在本機媒體庫中。

支援的影片格式包括常見的容器格式，例如 `mp4`、`mov`、`avi`、`mkv` 和 `webm`。Insight 還能識別 MJPEG 資源和 HEVC/H.265 媒體，以便進行支援特定編解碼器的串流。MJPEG 和 HEVC 媒體會保留，以便可以使用其原始編解碼器行為進行串流。

匯入媒體後，您可以篩選檔案清單、預覽選取的檔案、檢查其基本中繼資料，或刪除不再需要的檔案。在使用「媒體來源」設定串流來源之前，請先使用「媒體來源」，這樣您就可以知道哪些檔案可用、Insight 偵測到哪些編解碼器，以及它們是否可讀。

![Insight 媒體來源檢視畫面，顯示選取的影片預覽和媒體中繼資料。](../../images/insight-media-library.png)

「媒體來源」將匯入、檔案選取、預覽、中繼資料檢查和刪除操作結合在一個視窗中。從目錄匯入的資源會儲存在 `catalog/` 下，而 YouTube 影片片段會儲存在 `youtube/` 下，因此您可以識別檔案是如何進入媒體庫的。

## 串流媒體來源

「串流來源」檢視會將上傳的媒體檔案轉換為即時來源插槽。每個來源插槽都可以顯示一個 RTSP URL：

```text
rtsp://127.0.0.1:8554/src1
rtsp://127.0.0.1:8554/src2
rtsp://127.0.0.1:8554/src3
```

這些 URL 對於在與 Insight 相同的 SDK 容器中執行的應用程式而言是正確的。如果應用程式在 DevKit 或其他外部機器上執行，請使用 SDK 主機的 IP 位址，以及從 `neat --json` 中映射的 `rtsp.tcp` 主機連接埠。

Insight 會從已指派的媒體中選擇編解碼器和傳輸選項：

- 透過 RTSP 傳輸 H.264 媒體串流，格式為 H.264。
- 透過 RTSP 傳輸 HEVC/H.265 媒體串流，格式為 H.265。
- MJPEG 媒體可以透過 RTSP 以 MJPEG 格式串流，或透過 HTTP 以多部分 MJPEG 格式串流。

編碼器是由所選的媒體決定，且不會在使用者介面中手動更改。透過 RTSP 傳輸的 MJPEG 會被編碼成與 RTP 相容的 MJPEG，而 HTTP MJPEG 則可以保留 MJPEG 幀，以便進行類似相機的 HTTP 測試。

您可以將媒體指派給一個來源，啟動和停止個別的來源，自動將唯一的檔案指派給不同的來源插槽，批量啟動來源，停止所有串流，並複製串流 URL 以供應用程式或測試工具使用。

當您需要針對物件偵測、分割、追蹤、分類或 GenAI 視覺應用程式，建立可重複的輸入串流時，這個檢視畫面會很有用。

![ Insight 串流來源檢視畫面，顯示已指派的來源插槽和來源預覽。](../../images/insight-rtsp-source.png)

「串流來源」檢視畫面可讓您將媒體檔案指派給來源插槽，啟動或停止串流，複製作用中的串流 URL，並在將其連接到應用程式之前預覽所選的來源。

## 影片檢視器

視訊檢視器會顯示來自視訊轉發器的低延遲 WebRTC 串流。

對於頻道 `N`：

```text
video:    UDP 9000 + N
metadata: UDP 9100 + N
```

例如，頻道 `0` 使用視訊 UDP `9000` 和中繼資料 UDP `9100`；頻道 `1` 使用視訊 UDP `9001` 和中繼資料 UDP `9101`。

如果傳送者在 DevKit 或其他外部機器上執行，請使用從 `neat --json` 映射的 `videoUDP` 和 `metadataUDP` 主機連接埠範圍。 頻道數學運算相同，但起始連接埠可能不同。

檢視器可以呈現常用視覺輸出（包括物件偵測、分類、姿勢估計、分割和追蹤）的中繼資料疊加層。 檢視器設定可讓您調整疊加層行為，例如置信度閾值、ROI 顯示、追蹤歷史記錄和同步緩衝。 中繼資料時間戳使用來源 PTS 毫秒，如果無法使用，則會省略。

使用視訊檢視器進行確認：

- 應用程式正在將影片傳送到預期的頻道。
- 中繼資料即將傳送到對應的中繼資料通道。
- 疊圖會與影片畫面對齊。
- 瀏覽器播放功能運作正常。

![ Insight 影片檢視器顯示一個四通道 WebRTC 網格。](../../images/insight-video-viewer.png)

影片檢視器可以一次顯示一個或多個通道，並提供分頁和通道選擇控制項，以便進行更大規模的多串流測試。

## 周邊設備

周邊設備會列出連接至開發板的相機，並顯示每部相機所回報的模式。探索只會讀取裝置資訊，不會發佈串流，因此除了掃描讀取 MIPI 相機自身模式的短暫時間外，相機仍可供應用程式使用。相機匯出 API 也會從快取的掃描結果運作，而不接觸開發板。

### 選取的開發板

Insight 使用一個選取的開發板，並將其顯示在標頭中。選取它可開啟開發板設定，您可以在其中變更開發板、測試連線，或信任重新燒錄之開發板的主機金鑰。周邊設備與統計資料使用此選取項目。

開發板會依下列順序選取：

- **您輸入的開發板**：開啟開發板設定並提供位址、SSH 連接埠和使用者。**使用預設值**會返回自動選取。
- **安裝在開發板上的 Insight**：Insight 會檢查其執行所在的開發板。
- **Neat SDK**：以 `sima-cli sdk setup --devkit <ip>` 配對的 DevKit。

Insight 使用執行帳戶的金鑰透過 SSH 連線。它絕不會要求或儲存密碼。如果驗證失敗，頁面會顯示在開發板上授權金鑰的 `ssh-copy-id` 指令。重新燒錄開發板後，它會提供新的 SSH 主機金鑰；Insight 會拒絕連線，直到您比較指紋並選取 **信任新金鑰**。

### 相機和模式

選取 **重新整理** 以掃描開發板。Insight 透過 libcamera 和媒體圖尋找 MIPI 相機，並透過 V4L2 尋找 USB 相機。對於每部相機，它會顯示身分、連線、裝置識別碼、可用性，以及相機回報的像素格式、解析度和畫面播放速率。每部相機和模式都有支援等級：

| 等級 | 意義 |
| --- | --- |
| 已驗證 | 此模式已使用 Core `CameraInput` 驗證。 |
| 已回報 | 相機回報此模式，但尚未使用 Core 驗證。開始擷取時仍可能失敗。 |
| 不支援 | Core `CameraInput` 無法使用此模式。這包括 USB 相機、原始感測器格式，以及 NV12 以外的格式。 |

為讀取 MIPI 相機的模式，重新整理會透過 libcamera 短暫開啟相機，但不進行串流。其他應用程式正在使用的相機會被略過，並保留先前掃描的模式。可用性會指出占用相機的程序；Insight 只有在以 root 身分執行或開發板允許無密碼 `sudo` 時，才能看到其他使用者的程序，否則會回報 **未知**。

### 相機設定 API

此頁面可讓您檢查格式、解析度和畫面播放速率。目前不包含複製或下載動作。API 用戶端可將選取的模式 POST 至 `/api/peripherals/cameras/export`，並接收 Python（`pyneat.CameraInputOptions`）、C++ 和 JSON 表示法。請求必須包含同一份 `/api/peripherals` 快照中的 `generation`；若選取的開發板已變更，Insight 會回傳 `409 stale_snapshot`。只有在已安裝的 `libcamerasrc` 支援所需的擷取緩衝區選項時，才會包含 Apps `config.yaml` 的 `camera:` 區塊。匯出一律明確指定相機。對於 USB 相機，API 會傳回裝置描述元，而不是 `CameraInput` 設定。

在 Modalix DevKit 上測得的兩種行為會影響匯出。它允許 CPU 後援（`allow_cpu_fallback = True`），因為嚴格的零複製無法在該裝置上啟動。此外，相機會以 libcamera 所選感測器模式的畫面播放速率傳送，而不是要求的速率：當要求 15 或 30 fps 時，1920×1080 的 IMX477 傳送速率約為 66 fps。如果需要較少的畫面，請在應用程式中捨棄畫面。

## 統計資料

「統計資料」會從 Sentinel（即 `simaai-sentinel` 常駐程式）讀取開發板本身的遙測資料，讓您能將應用程式行為與裝置行為分開。遺漏的畫面可能來自串流路徑，但也可能與開發板功率、晶片溫度、CPU 負載或記憶體壓力相關。

「統計資料」會在選取的開發板上運作，此開發板是在與周邊設備頁面相同的 **開發板** 面板中選取。

### Sentinel 常駐程式

當該開發板上缺少 Sentinel、Sentinel 已停止或無法連線時，頁面會優先顯示此狀況。若缺少 Sentinel，請選取 **安裝 Sentinel**：Insight 會在開發板本身執行 `sima-cli neat install sentinel`，這需要開發板上有 `sima-cli` 以及無密碼 `sudo`。若缺少其中任一項，頁面會改為列出要在開發板的 shell 中執行的指令。已安裝且正在執行的常駐程式絕不會從此處重新安裝，因為安裝程式會重新啟動它，而中斷進行中的追蹤。

遭拒或失敗的安裝會以安裝問題回報，而不是讀取失敗：頁面會說明安裝未進行，並以開發板本身的說明提供原因——沒有 `sima-cli`、沒有無密碼 `sudo`、安裝程式以非零值結束，或安裝程式已完成但服務仍處於停止狀態——並將安裝程式的輸出保留在 **安裝程式輸出** 之下。

### 即時指標

DevKit 檢視的版面配置與 Sentinel 本身的終端機儀表板（`simaai-sentinel ops`）相同。狀態列會顯示讀數是否為即時，以及目前 Sentinel 工作階段的開始時間，工作階段平均值和峰值即以此工作階段為範圍。**匯出 CSV** 會下載 Sentinel 在該工作階段中保留的每個樣本的所有指標（最近 240 個，約八分鐘；若需要更長的時間，請在 **執行記錄** 下錄製追蹤），而 **暫停更新** 會停止輪詢。其下方有六個分頁：

- **概觀**：最熱溫度感測器、開發板功率、CPU 使用率、Linux 記憶體、MLA 記憶體和網路流量的圖表，下方摺疊著 **所有指標**，依 Sentinel 的順序列出每個指標。
- **溫度**：最熱感測器隨時間的變化，接著以小型圖表呈現每個感測器群組（MLA、APU、CVU、TOP、Board）。
- **功率**：以數字呈現目前、工作階段平均和工作階段峰值功率，時間範圍內的開發板功率並標示工作階段平均值，以及堆疊的電源軌，使頂端邊緣即為開發板總功率。
- **系統**：**CPU 與記憶體** 以圖表呈現 CPU 使用率、平均負載、Linux 記憶體、MLA 記憶體和 EV74 CMA 使用量。**各核心 CPU** 是以單一藍色呈現的負載熱圖，每個核心一列，時間範圍內每 10 秒一欄，並顯示每個核心的一分鐘平均值及最忙碌的核心；平均值超過核心限制時會變成琥珀色或紅色。
- **儲存空間與網路**：eMMC 使用量、網路接收與傳送、eMMC 讀取與寫入，以及其指標。
- **執行記錄**：錄製追蹤，並開啟、比較或刪除已儲存的執行記錄。比較功能會在所有選取的執行記錄共同涵蓋的時間內，以配合這些執行記錄調整的刻度，疊加每個選取執行記錄的一個數列（總功率、最高溫度、CPU、負載、RAM、MLA 記憶體或 EV74 CMA），並顯示每個執行記錄的最小值、平均值、中位數、P95、最大值、相對於基準的變化以及能量；各指標的比較摺疊於其下方。

圖表使用固定刻度（百分比為 0-100，溫度為 40-90 °C，其他值則為高於其峰值的整齊數值），顯示 Sentinel 定義的警告和嚴重等級，並在滑鼠停留時顯示該點所有數列的值。顏色代表狀態：在讀數超過警告或嚴重等級之前，圖表為藍色，超過後則變為琥珀色或紅色。當分頁中的指標超過閾值時，分頁名稱會加上標記。開發板無法測量的指標會顯示為破折號（—），而不是零。

圖表涵蓋 Sentinel 保留的整個時間範圍，即 240 個樣本（約八分鐘）：首次讀取開發板時，以及輪詢暫停超過一分鐘後，Insight 會從 Sentinel 本身的快取取得這些樣本，之後在分頁開啟且可見時，每兩秒新增一個樣本。當瀏覽器分頁隱藏或離開此檢視時，輪詢也會停止。

如果在您檢視時開發板停止回應，輪詢會停止，但面板會保留，顯示最後讀取的值以及開發板本身對失敗原因的說明，而不會清空頁面。選取不同的開發板則是另一回事：這會先清除所有內容，因此一個開發板的數值絕不會顯示在另一個開發板的名稱之下。

### 追蹤與執行記錄

追蹤會記錄工作負載前後的每個樣本。為其命名，視需要新增備註和標籤，然後選取 **開始追蹤**；**停止追蹤** 會將其儲存為開發板上的執行記錄。Sentinel 一次只記錄一個追蹤，並會拒絕已儲存執行記錄已使用的名稱。已儲存的執行記錄會與其狀態、開始時間、持續時間、Sentinel 在該次執行期間測得的能量以及樣本數一起列出，且在常駐程式重新啟動後仍會保留。開啟執行記錄即可查看其摘要：記錄的每個指標，以及當時有效的標籤、單位、群組和閾值，還有該執行記錄樣本中的最小值、最大值和平均值。在執行期間任何時間點超過警告或嚴重閾值的指標會加上標記。只擷取到一個樣本的執行記錄會以擷取當下的時刻呈現，而不是從該時刻到其本身的範圍，其平均值、最小值和最大值會標示為它們共同的單一值。執行記錄的中繼資料——名稱、備註、取樣間隔、Sentinel 版本，以及執行所在的開發板——位於其下方。

勾選執行記錄會顯示工具列，列出已選取的數量以及可執行的動作。選取二到八個並選取 **比較**，即可將指標排成列、執行記錄排成欄。Sentinel 會以一個基準執行記錄來衡量比較，該基準會與每個執行記錄的備註一起標示在標頭中；其他每個儲存格會顯示該指標在該執行記錄中的平均值，旁邊則是相對於基準的百分比變化。小到無法顯示的變化會顯示為 “<0.01%”，而不是無變化。

當儲存格以 “—” 取代變化時，表示 Sentinel 未提供變化值，表格會說明適用的是哪個原因，而不是用一個破折號代表所有原因。將滑鼠停留在 “—” 上、以 Tab 鍵移至該處或點選它，即可在旁邊看到原因；螢幕閱讀器會將原因與破折號一起朗讀。原因如下：

- **Sentinel 未發佈此項目的變化。** 執行記錄總計（持續時間、能量和樣本數）會按執行記錄回報，不含百分比。
- **基準測得 0，而從 0 起算沒有百分比變化。** 基準確實測量了此指標；只是從零起算不存在百分比。這在閒置基準的各核心 CPU 使用率中很常見，而且往往正是變化最大之處：基準中平均 0%、另一個執行記錄中為 5.9% 的核心在此會顯示 “—”，因此請比較兩個值，而不是變化。
- **基準執行記錄沒有該指標的值。** 這是基準從未測量該指標的唯一情況。
- **此執行記錄沒有該指標的值。** 若執行記錄有列出，但 Sentinel 未為其產生任何摘要，則整欄都會如此顯示，並在表格上方特別指出。

執行記錄總計會以檢視其他部分所用的單位顯示：Sentinel 以毫秒回報的持續時間會以秒顯示，能量則以焦耳顯示。

如果選取中的執行記錄在開發板上遭到刪除，其列會從清單中消失，也不再有可用來取消選取的核取方塊，因此每次比較都會因它而失敗。Insight 會指出 Sentinel 已不再列出的任何選取執行記錄，並提供將其從選取項目中移除的選項。

比較會以單一逗號分隔的名稱清單要求執行記錄，因此追蹤名稱不能包含逗號：否則要求會被解讀為開發板上不存在的兩個執行記錄，並以沒有人選取的執行記錄名稱失敗。Insight 會在您開始追蹤時拒絕此類名稱，並指出任何已儲存且名稱含有逗號的執行記錄，而不是讓比較因其而失敗。

### 先前開發板的值

讀取開發板需要一次 SSH 往返，因此回應可能在您選取另一個開發板之後才抵達。選取另一個開發板會取消所有仍在從先前開發板傳回途中的回應：新的開發板會立即接受檢查，而舊開發板延遲抵達的回應會被捨棄，不會顯示為新開發板的值。**停止追蹤** 會指出其追蹤讀取自哪個開發板，並會遭到拒絕，而不會停止另一個開發板上的追蹤。當選取的開發板在其他地方（另一個瀏覽器分頁或 API 用戶端）變更時，頁面上既有的值會標示其來源開發板，並提供重新讀取的方式。

### Insight 主機

「統計資料」有兩個檢視：**DevKit** 和 **主機**；以上所有內容皆為 DevKit 檢視。主機檢視會從 `/api/metrics` 回報 Insight 本身執行所在的機器（SDK 容器，或安裝 Insight 的開發板）：CPU 負載、記憶體、磁碟，以及平台有提供時的溫度。它回答的問題與 DevKit 檢視不同，例如容器的磁碟空間是否即將用盡，且每 15 秒讀取一次，而不是每兩秒。設定舊版 `REMOTE_DEVKIT` 組態時，此面板會改為回報該連線，並加以說明。當端點完全沒有傳回讀數時，面板會說明這一點，而不是列出其標籤並搭配破折號。

### NEAT 分析時間軸

在主機檢視的 Insight 主機面板下方，分析時間軸會繪製 Insight 從執行中應用程式串流傳輸的分析事件中的數值欄位。它與 Sentinel 無關：它測量的是應用程式，而不是裝置。

## 系統資訊

系統資訊面板會摘要說明 Insight 可以檢視的環境。在 Neat 開發環境中，它可以顯示 SDK 和元件資訊、Insight 狀態、更新資訊，以及公開的連接埠對應，例如 `mainUI` 和 `videoUI`。

當 URL 與預設連接埠不符時，這是您應該首先檢查的地方。Insight 會讀取可用的連接埠對應，並在開啟檢視器時使用對應的 `videoUI` 連接埠。對於命令列工作流程，`neat --json` 會顯示相同的連接埠對應資訊。
