# 사용자 인터페이스

Insight는 비전 애플리케이션을 검증하는 동안 수행하는 개발 작업, 즉 파일을 검사하고, 미디어를 준비하고, 소스를 시작하고, 출력을 확인하고, 런타임 상태를 모니터링하는 작업을 중심으로 구성됩니다.

## 작업 공간

작업 공간 보기에서는 Insight에 표시되는 프로젝트 파일을 탐색할 수 있습니다. Neat 개발 환경에서는 일반적으로 이것이 `/workspace`이며, SDK 외부에서는 Insight가 현재 작업 디렉터리로 돌아갑니다.

작업 공간을 사용하여 다음을 수행하세요.

- 소스 파일, 구성 파일, 모델 아티팩트 및 생성된 출력물을 검색하고 탐색합니다.
- 미리보기 텍스트, 코드, 마크다운, 이미지 및 선택한 이진 파일을 확인합니다.
- 수동으로 압축을 풀지 않고 MPK 패키지 아카이브를 검사합니다.
- MLA 통계, MPK 매니페스트, 파이프라인 시퀀스 파일과 같은 특수 개발 결과물을 확인합니다.

작업 공간은 애플리케이션이 여러 빌드 결과물과 로그를 생성할 때 특히 유용합니다. 이를 통해 동일한 개발 세션 내에서 해당 결과물을 브라우저에서 쉽게 확인하고 검사할 수 있습니다.

![ Insight 작업 공간 보기에는 파이프라인 시퀀스 그래프와 작업 공간 결과물이 표시됩니다.](../../images/insight-workspace-overview.png)

## 미디어 소스

미디어 소스는 애플리케이션 테스트에 사용되는 미디어 파일을 추가하고 관리하는 곳입니다. **미디어 가져오기**를 선택하여 가져오기 대화 상자를 열고 다음 세 가지 소스 중 하나를 선택합니다.

- **로컬 파일**: 컴퓨터에서 하나 이상의 파일을 선택하거나 끌어서 놓습니다. H.264 MP4 파일을 업로드하면 B 프레임을 비활성화하여 지연 시간이 짧은 재생을 위해 정규화되면서 원본 프레임 속도는 유지됩니다.
- **카탈로그**: SiMa의 엄선된 비디오 카탈로그에서 비디오를 가져와 알려진 자산을 사용하여 반복적인 테스트를 수행합니다. 자산 유형 또는 이름별로 찾아보거나, 카탈로그를 검색하고, 해상도, 프레임 속도 및 코덱별로 필터링하고, 비디오를 미리 본 다음, 하나의 변형을 가져오거나 여러 개의 일치하는 자산을 선택하여 가져올 수 있습니다.
- **YouTube**: 일반 YouTube 동영상 URL을 붙여넣고, 유효성을 검사하여 미리보기를 표시한 다음, 시작 시간, 클립 길이 및 출력 프로필을 선택합니다. Insight는 `1080p30`, `720p30` 또는 `480p30`에서 1분, 3분 또는 5분 클립을 지원합니다. 가져온 클립은 B 프레임이 비활성화된 WebRTC 호환 H.264로 변환됩니다. 활성 라이브 스트림은 지원되지 않으므로 일반 동영상 또는 보관된 라이브 스트림을 사용하십시오.

카탈로그 및 YouTube 가져오기 기능은 네트워크 연결이 필요합니다. Insight는 미디어를 다운로드하고 준비하는 동안 진행 상황을 표시한 다음 결과를 로컬 미디어 라이브러리에 저장합니다.

지원되는 비디오 형식에는 `mp4`, `mov`, `avi`, `mkv` 및 `webm`과 같은 일반적인 컨테이너 형식이 포함됩니다. Insight는 또한 코덱을 인식하는 스트리밍을 위해 MJPEG 자산 및 HEVC/H.265 미디어를 인식합니다. MJPEG 및 HEVC 미디어는 원래 코덱 동작으로 스트리밍할 수 있도록 보존됩니다.

미디어를 가져온 후 파일 목록을 필터링하고, 선택한 파일을 미리 보거나, 기본 메타데이터를 검사하거나, 더 이상 필요하지 않은 파일을 삭제할 수 있습니다. 스트리밍 소스를 구성하기 전에 미디어 소스를 사용하여 사용 가능한 파일, Insight가 감지한 코덱, 파일이 읽을 수 있는지 확인하십시오.

![Insight 미디어 소스 보기에서는 선택한 비디오 미리보기와 미디어 메타데이터가 표시됩니다.](../../images/insight-media-library.png)

미디어 소스는 가져오기, 파일 선택, 미리 보기, 메타데이터 검사 및 삭제 작업을 하나의 보기로 결합합니다. 가져온 카탈로그 자산은 `catalog/`에 저장되고, YouTube 클립은 `youtube/`에 저장되므로 파일이 라이브러리에 어떻게 들어왔는지 확인할 수 있습니다.

## 스트리밍 소스

스트리밍 소스 보기에서는 업로드된 미디어 파일을 실시간 소스 슬롯으로 변환합니다. 각 소스 슬롯은 RTSP URL을 표시할 수 있습니다.

```text
rtsp://127.0.0.1:8554/src1
rtsp://127.0.0.1:8554/src2
rtsp://127.0.0.1:8554/src3
```

해당 URL은 Insight와 동일한 SDK 컨테이너에서 실행되는 애플리케이션에 대해 올바릅니다. 애플리케이션이 DevKit 또는 다른 외부 장치에서 실행되는 경우, SDK 호스트 IP 주소와 `neat --json`에서 매핑된 `rtsp.tcp` 호스트 포트를 사용하십시오.

Insight는 할당된 미디어에서 코덱 및 전송 옵션을 선택합니다.

- H.264 미디어 스트림을 RTSP를 통해 H.264 형식으로 전송합니다.
- H.265 코덱으로 RTSP를 통해 HEVC/H.265 미디어 스트림을 전송합니다.
- MJPEG 미디어는 MJPEG 형식으로 RTSP를 통해 스트리밍하거나 HTTP를 통해 멀티파트 MJPEG 형식으로 스트리밍할 수 있습니다.

코덱은 선택한 미디어에 따라 결정되며, UI에서 수동으로 변경할 수 없습니다. RTSP를 통해 전송되는 MJPEG은 RTP 호환 MJPEG으로 인코딩되며, HTTP MJPEG은 카메라 스타일의 HTTP 테스트를 위해 MJPEG 프레임을 유지할 수 있습니다.

미디어를 소스에 할당하고, 개별 소스를 시작 및 중지하고, 소스 슬롯 간에 고유한 파일을 자동으로 할당하고, 여러 소스를 한 번에 시작하고, 모든 스트림을 중지하고, 애플리케이션 또는 테스트 도구에서 사용할 수 있도록 스트림 URL을 복사할 수 있습니다.

이 뷰는 객체 감지, 분할, 추적, 분류 또는 GenAI 비전 애플리케이션에 대해 반복 가능한 입력 스트림이 필요한 경우에 유용합니다.

![ Insight 스트리밍 소스 뷰는 할당된 소스 슬롯과 소스 미리보기를 보여줍니다.](../../images/insight-rtsp-source.png)

스트리밍 소스 뷰를 사용하면 미디어 파일을 소스 슬롯에 할당하고, 스트림을 시작하거나 중지하고, 활성 스트림 URL을 복사하고, 애플리케이션에 연결하기 전에 선택한 소스를 미리 볼 수 있습니다.

## 비디오 뷰어

비디오 뷰어는 비디오 전달 장치에서 전송되는 지연 시간이 짧은 WebRTC 스트림을 표시합니다.

채널 `N`의 경우:

```text
video:    UDP 9000 + N
metadata: UDP 9100 + N
```

예를 들어, 채널 `0`은 비디오 UDP `9000` 및 메타데이터 UDP `9100`를 사용하고, 채널 `1`은 비디오 UDP `9001` 및 메타데이터 UDP `9101`를 사용합니다.

송신자가 DevKit 또는 다른 외부 장치에서 실행되는 경우, `neat --json`에서 매핑된 비디오 `videoUDP` 및 메타데이터 `metadataUDP` 호스트 포트 범위를 사용합니다. 채널 계산은 동일하지만 시작 포트는 다를 수 있습니다.

뷰어는 객체 감지, 분류, 자세 추정, 분할 및 추적을 포함한 일반적인 비전 출력에 대한 메타데이터 오버레이를 렌더링할 수 있습니다. 뷰어 설정을 통해 신뢰도 임계값, ROI 표시, 추적 기록 및 동기화 버퍼링과 같은 오버레이 동작을 조정할 수 있습니다. 메타데이터 타임스탬프는 소스 PTS 밀리초를 사용하며, 사용할 수 없는 경우 생략됩니다.

비디오 뷰어를 사용하여 확인하십시오.

- 애플리케이션이 예상된 채널로 비디오를 전송하고 있습니다.
- 메타데이터가 해당 메타데이터 채널을 통해 전송되고 있습니다.
- 오버레이가 비디오 프레임과 정렬됩니다.
- 브라우저에서 재생이 원활하게 이루어집니다.

![ Insight 비디오 뷰어는 4개의 채널을 표시하는 WebRTC 그리드를 보여줍니다.](../../images/insight-video-viewer.png)

비디오 뷰어는 한 번에 하나 이상의 채널을 표시할 수 있으며, 더 많은 멀티 스트림 테스트를 위해 페이지 매김 및 채널 선택 컨트롤을 제공합니다.

## 주변 장치

주변 장치는 보드에 연결된 카메라와 각 카메라가 보고하는 모드를 표시합니다. 카메라는 보드의 SiMa Sentinel이 검색하고, Insight는 Sentinel의 카탈로그를 읽습니다. 검색은 장치 정보만 읽고 카메라를 열거나 스트리밍하지 않으므로 카메라는 애플리케이션에서 계속 사용할 수 있습니다. 카메라 내보내기 API는 보드에 접근하지 않고 마지막 스캔으로 동작합니다.

### 선택한 보드

Insight는 헤더에 표시된 하나의 선택된 보드로 작업합니다. 이를 선택하면 보드 설정이 열리며 보드를 변경하거나, 연결을 테스트하거나, 다시 플래시된 보드의 호스트 키를 신뢰할 수 있습니다. 주변 장치는 이 선택을 사용합니다. 통계 뷰는 여전히 기존 로컬 또는 `cfg.json` 대상을 사용하며 아직 이 선택을 따르지 않습니다.

보드는 다음 순서로 선택됩니다.

- **직접 입력한 보드**: 보드 설정을 열고 주소, SSH 포트 및 사용자를 입력합니다. **기본값 사용**을 선택하면 자동 선택으로 돌아갑니다.
- **보드에 설치된 Insight**: Insight가 실행 중인 보드를 검사합니다.
- **Neat SDK**: `sima-cli sdk setup --devkit <ip>`로 페어링된 DevKit입니다.

Insight는 실행 계정의 키로 SSH에 연결합니다. 비밀번호를 요청하거나 저장하지 않습니다. 인증에 실패하면 페이지에 보드에서 키를 승인하는 `ssh-copy-id` 명령이 표시됩니다. 보드를 다시 플래시하면 새 SSH 호스트 키가 제시됩니다. Insight는 지문을 비교하고 **새 키 신뢰**를 선택할 때까지 연결을 거부합니다.

### 카메라 및 모드

**새로 고침**을 선택하여 보드를 스캔합니다. Insight는 SiMa Sentinel에 다시 스캔하도록 요청하고 결과를 기다립니다. Sentinel은 미디어 그래프와 ISP를 통해 MIPI 카메라를, V4L2를 통해 USB 카메라를 찾습니다. Sentinel이 설치되어 있지 않거나, 실행 중이 아니거나, 주변 장치를 보고하기에는 너무 오래된 경우 페이지에 그 내용이 표시됩니다. `sima-cli neat install sentinel`로 설치하거나 업데이트하세요. 각 카메라의 ID, 연결, 장치 식별자, 사용 가능 여부와 카메라가 보고하는 픽셀 형식, 해상도 및 프레임 속도를 표시합니다. 각 카메라와 모드에는 지원 수준이 있습니다.

| 수준 | 의미 |
| --- | --- |
| 검증됨 | 보드의 Neat Core 지원 규칙이 이 모드를 Core `CameraInput`에서 사용할 수 있다고 판단합니다. |
| 지원되지 않음 | Neat Core 규칙이 이 모드를 거부합니다. 예를 들어 USB 카메라와 NV12 이외의 형식입니다. 페이지에는 Sentinel이 보고한 이유가 표시됩니다. 보드에 Neat Core가 없으면 어떤 모드도 지원되지 않습니다. |

Sentinel은 Neat Core가 보드에 설치하는 지원 규칙을 적용합니다. 사용 가능 여부는 Insight가 판단합니다. 새로 고침 중에 각 카메라의 장치 노드를 점유한 프로세스를 확인하고, 카메라를 점유한 프로세스를 표시합니다. Insight는 root로 실행되거나 보드가 비밀번호 없는 `sudo`를 허용할 때만 다른 사용자의 프로세스를 볼 수 있으며, 그렇지 않으면 **알 수 없음**으로 보고합니다.

### 카메라 구성 API

페이지에서는 형식, 해상도 및 프레임 속도를 검사할 수 있습니다. 현재 복사 또는 다운로드 작업은 제공하지 않습니다. API 클라이언트는 선택한 모드를 `/api/peripherals/cameras/export`에 POST하고 Python(`pyneat.CameraInputOptions`), C++ 및 JSON 표현을 받을 수 있습니다. Insight는 보드의 `libcamerasrc`를 읽지 않으므로 내보내기는 캡처 버퍼 수를 설정하지 않으며 Apps `config.yaml`의 `camera:` 블록을 포함하지 않습니다. 내보내기에는 항상 카메라 이름이 명시됩니다. USB 카메라의 경우 API는 `CameraInput` 구성이 아니라 장치 설명자를 반환합니다.

Modalix DevKit에서 측정된 두 가지 동작이 내보내기에 반영됩니다. 엄격한 제로 카피로 시작되지 않았기 때문에 CPU 폴백(`allow_cpu_fallback = True`)을 허용합니다. 또한 카메라는 요청한 속도가 아니라 libcamera가 선택한 센서 모드의 프레임 속도로 전달합니다. 1920×1080의 IMX477은 15 또는 30 fps를 요청했을 때 약 66 fps를 전달했습니다. 더 적은 프레임이 필요하면 애플리케이션에서 프레임을 삭제하십시오.

### 마이크

**새로 고침**은 SiMa Sentinel이 보고하는 모든 ALSA 캡처 장치(USB 또는 온보드)도 나열합니다. 각 마이크에 대해 Insight는 이름, 장치를 여는 데 사용할 ALSA 장치 이름(예: `hw:CARD=Nano,DEV=0`), 사용 가능 여부, 그리고 USB 오디오 장치의 경우 캡처하는 샘플 형식, 채널 수, 비트 깊이, 샘플 속도를 표시합니다. 온보드 사운드 카드는 이를 보고하지 않으며, 페이지에 그렇게 표시됩니다.

검색은 사운드 장치를 열지 않습니다. Sentinel은 `/proc/asound`와 sysfs를 읽습니다. 커널이 캡처 장치가 열려 있다고 보고하면 마이크는 **사용 중**이 되고, Insight는 확인할 수 있는 경우 해당 프로세스를 표시합니다. PulseAudio 같은 사운드 서버가 카드의 믹서만 잡고 있는 경우는 포함되지 않습니다. USB 마이크는 분리했다가 다시 연결해도, 카드 번호가 바뀌어도 같은 ID를 유지합니다.

마이크 소리를 들으려면 **마이크 테스트**를 선택하고 말하세요. 레벨 미터에 마이크가 듣는 소리가 표시됩니다. 끝나면 **녹음 중지**를 선택하세요(테스트는 30초 후 자동으로 중지됩니다). Insight가 페이지에서 녹음을 재생합니다. **재생 중지**로 재생을 끝냅니다. 녹음이 약 -60 dBFS 아래에 머물면 페이지에 아무것도 녹음되지 않았다고 표시됩니다. 마이크의 음소거 버튼과 게인을 확인하세요. 장치를 여는 것은 테스트뿐이며, 녹음하는 동안만 엽니다. 녹음하기 전에 Insight는 Sentinel의 카탈로그를 다시 읽고 Sentinel이 지정한 장치에서만 녹음합니다. 마지막 스캔 이후 보드의 장치가 바뀌었다면 페이지에서 먼저 새로 고침하라고 안내합니다. 다른 애플리케이션이 마이크를 열고 있으면 테스트가 거부되고 해당 애플리케이션은 그대로 둡니다. Core에는 오디오 입력이 없으므로 Insight는 오디오 입력을 구성하지 않습니다.

## 통계

현재 버전의 통계 보기 기능은 임시 자리 표시자입니다. 애플리케이션이 실행되는 동안 시스템 부하 및 런타임 지표가 표시될 위치를 나타내며, 여기에는 CPU, 메모리, 디스크, 사용 가능한 경우 온도, MLA 메모리, 그리고 Insight를 통해 스트리밍되는 프로파일링 타임라인 데이터가 포함됩니다.

이 기능은 다음 버전에 완성될 예정입니다. 완성되면 애플리케이션 동작과 시스템 동작을 분리해야 할 때 통계 기능을 사용하십시오. 예를 들어, 프레임 드롭 문제가 애플리케이션 스트림 경로에서 발생할 수 있지만, CPU 부하, 메모리 사용량 또는 장치 런타임 상태와 관련될 수도 있습니다.

## 시스템 정보

시스템 정보 패널은 Insight가 확인할 수 있는 환경을 요약하여 보여줍니다. Neat 개발 환경에서는 SDK 및 구성 요소 정보, Insight 상태, 업데이트 정보, 그리고 `mainUI` 및 `videoUI`와 같은 노출된 포트 매핑을 표시할 수 있습니다.

URL이 기본 포트와 일치하지 않을 때 가장 먼저 확인해야 하는 곳입니다. Insight는 사용 가능한 포트 맵을 읽고 뷰어를 열 때 매핑된 `videoUI` 포트를 사용합니다. 명령줄 워크플로의 경우, `neat --json`은 동일한 포트 맵 정보를 표시합니다.
