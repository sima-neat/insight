# 사용자 인터페이스

Insight는 비전 애플리케이션을 검증하는 동안 수행하는 개발 작업, 즉 파일을 검사하고, 미디어를 준비하고, 소스를 시작하고, 출력을 확인하고, 런타임 상태를 모니터링하는 작업을 중심으로 구성됩니다.

## 작업 공간

작업 공간 보기에서는 Insight에 표시되는 프로젝트 파일을 탐색할 수 있습니다. Neat 개발 환경에서는 일반적으로 이것이 `/workspace`이며, SDK 외부에서는 Insight가 현재 작업 디렉터리로 돌아갑니다.

작업 공간을 사용하여 다음을 수행하세요.

- 소스 파일, 구성 파일, 모델 아티팩트 및 생성된 출력물을 검색하고 탐색합니다.
- 미리보기 텍스트, 코드, 마크다운, 이미지 및 선택한 이진 파일을 확인합니다.
- 수동으로 압축을 풀지 않고 MPK 패키지 아카이브를 검사합니다.
- MLA 통계, MPK 매니페스트, 파이프라인 시퀀스 파일과 같은 특수 개발 결과물을 확인합니다.

작업 공간은 애플리케이션이 여러 빌드 결과물과 로그를 생성할 때 특히 유용합니다. 이를 통해 동일한 개발 세션 내에서 해당 결과물을 브라우저에서 쉽게 확인하고 검사할 수 있습니다.

![ Insight 작업 공간 보기에는 파이프라인 시퀀스 그래프와 작업 공간 결과물이 표시됩니다.](../../images/insight-workspace-overview.png)

## 미디어 소스

미디어 소스는 애플리케이션 테스트에 사용되는 미디어 파일을 추가하고 관리하는 곳입니다. **미디어 가져오기**를 선택하여 가져오기 대화 상자를 열고 다음 세 가지 소스 중 하나를 선택합니다.

- **로컬 파일**: 컴퓨터에서 하나 이상의 파일을 선택하거나 끌어서 놓습니다. H.264 MP4 파일을 업로드하면 B 프레임을 비활성화하여 지연 시간이 짧은 재생을 위해 정규화되면서 원본 프레임 속도는 유지됩니다.
- **카탈로그**: SiMa의 엄선된 비디오 카탈로그에서 비디오를 가져와 알려진 자산을 사용하여 반복적인 테스트를 수행합니다. 자산 유형 또는 이름별로 찾아보거나, 카탈로그를 검색하고, 해상도, 프레임 속도 및 코덱별로 필터링하고, 비디오를 미리 본 다음, 하나의 변형을 가져오거나 여러 개의 일치하는 자산을 선택하여 가져올 수 있습니다.
- **YouTube**: 일반 YouTube 동영상 URL을 붙여넣고, 유효성을 검사하여 미리보기를 표시한 다음, 시작 시간, 클립 길이 및 출력 프로필을 선택합니다. Insight는 `1080p30`, `720p30` 또는 `480p30`에서 1분, 3분 또는 5분 클립을 지원합니다. 가져온 클립은 B 프레임이 비활성화된 WebRTC 호환 H.264로 변환됩니다. 활성 라이브 스트림은 지원되지 않으므로 일반 동영상 또는 보관된 라이브 스트림을 사용하십시오.

카탈로그 및 YouTube 가져오기 기능은 네트워크 연결이 필요합니다. Insight는 미디어를 다운로드하고 준비하는 동안 진행 상황을 표시한 다음 결과를 로컬 미디어 라이브러리에 저장합니다.

지원되는 비디오 형식에는 `mp4`, `mov`, `avi`, `mkv` 및 `webm`과 같은 일반적인 컨테이너 형식이 포함됩니다. Insight는 또한 코덱을 인식하는 스트리밍을 위해 MJPEG 자산 및 HEVC/H.265 미디어를 인식합니다. MJPEG 및 HEVC 미디어는 원래 코덱 동작으로 스트리밍할 수 있도록 보존됩니다.

미디어를 가져온 후 파일 목록을 필터링하고, 선택한 파일을 미리 보거나, 기본 메타데이터를 검사하거나, 더 이상 필요하지 않은 파일을 삭제할 수 있습니다. 스트리밍 소스를 구성하기 전에 미디어 소스를 사용하여 사용 가능한 파일, Insight가 감지한 코덱, 파일이 읽을 수 있는지 확인하십시오.

![Insight 미디어 소스 보기에서는 선택한 비디오 미리보기와 미디어 메타데이터가 표시됩니다.](../../images/insight-media-library.png)

미디어 소스는 가져오기, 파일 선택, 미리 보기, 메타데이터 검사 및 삭제 작업을 하나의 보기로 결합합니다. 가져온 카탈로그 자산은 `catalog/`에 저장되고, YouTube 클립은 `youtube/`에 저장되므로 파일이 라이브러리에 어떻게 들어왔는지 확인할 수 있습니다.

## 스트리밍 소스

스트리밍 소스 보기에서는 업로드된 미디어 파일을 실시간 소스 슬롯으로 변환합니다. 각 소스 슬롯은 RTSP URL을 표시할 수 있습니다.

```text
rtsp://127.0.0.1:8554/src1
rtsp://127.0.0.1:8554/src2
rtsp://127.0.0.1:8554/src3
```

해당 URL은 Insight와 동일한 SDK 컨테이너에서 실행되는 애플리케이션에 대해 올바릅니다. 애플리케이션이 DevKit 또는 다른 외부 장치에서 실행되는 경우, SDK 호스트 IP 주소와 `neat --json`에서 매핑된 `rtsp.tcp` 호스트 포트를 사용하십시오.

Insight는 할당된 미디어에서 코덱 및 전송 옵션을 선택합니다.

- H.264 미디어 스트림을 RTSP를 통해 H.264 형식으로 전송합니다.
- H.265 코덱으로 RTSP를 통해 HEVC/H.265 미디어 스트림을 전송합니다.
- MJPEG 미디어는 MJPEG 형식으로 RTSP를 통해 스트리밍하거나 HTTP를 통해 멀티파트 MJPEG 형식으로 스트리밍할 수 있습니다.

코덱은 선택한 미디어에 따라 결정되며, UI에서 수동으로 변경할 수 없습니다. RTSP를 통해 전송되는 MJPEG은 RTP 호환 MJPEG으로 인코딩되며, HTTP MJPEG은 카메라 스타일의 HTTP 테스트를 위해 MJPEG 프레임을 유지할 수 있습니다.

미디어를 소스에 할당하고, 개별 소스를 시작 및 중지하고, 소스 슬롯 간에 고유한 파일을 자동으로 할당하고, 여러 소스를 한 번에 시작하고, 모든 스트림을 중지하고, 애플리케이션 또는 테스트 도구에서 사용할 수 있도록 스트림 URL을 복사할 수 있습니다.

이 뷰는 객체 감지, 분할, 추적, 분류 또는 GenAI 비전 애플리케이션에 대해 반복 가능한 입력 스트림이 필요한 경우에 유용합니다.

![ Insight 스트리밍 소스 뷰는 할당된 소스 슬롯과 소스 미리보기를 보여줍니다.](../../images/insight-rtsp-source.png)

스트리밍 소스 뷰를 사용하면 미디어 파일을 소스 슬롯에 할당하고, 스트림을 시작하거나 중지하고, 활성 스트림 URL을 복사하고, 애플리케이션에 연결하기 전에 선택한 소스를 미리 볼 수 있습니다.

### 웹캠을 소스로 사용하기

브라우저가 실행되는 컴퓨터에 연결된 웹캠을 라이브 소스로 사용할 수 있으므로, 먼저 파일을 보드에 복사하지 않고 실제 카메라로 애플리케이션을 테스트할 수 있습니다.

1. Media Sources로 이동하여 **로컬 카메라** 아래에서 **카메라 접근 활성화**를 선택합니다. 브라우저가 카메라 권한을 요청하며, Insight는 대신 권한을 부여할 수 없습니다.
2. 접근을 허용하면 각 소스 드롭다운에서 비디오 파일 위의 **카메라** 그룹에 카메라가 나타납니다:

   ```text
   Not assigned
   Cameras
     Integrated Camera
     USB Camera
   Video files
     catalog/parking_garage_cars/parking_garage_cars_1080p.mp4
   ```

3. 소스 슬롯에 사용할 카메라를 선택한 다음 **시작**을 선택합니다. 행에 `[CAM]` 배지가 표시되고(비디오 파일은 `[VID]`), 브라우저가 카메라를 Insight에 게시하며 슬롯 상태가 `Live`로 표시됩니다.
4. **URL 복사**로 RTSP URL을 얻고 파일 소스와 동일하게 애플리케이션에 지정합니다.

카메라가 연결되거나 분리되면 목록이 갱신됩니다. 웹캠 소스는 H.264 비디오만 게시합니다.

소스 목록 옆의 미리보기는 캡처 중인 로컬 카메라 피드를 표시합니다. 보드가 수신한 비디오가 아니며 수신 애플리케이션이 경험하는 지연도 보여 주지 않습니다. 게시에 실패하면 캡처가 중지되고 미리보기가 지워집니다.

**중지** 선택, 카메라 분리 또는 브라우저 탭 닫기는 스트림을 종료하고 슬롯을 `Idle`로 되돌립니다. **모두 중지**, **초기화** 및 **자동 할당**도 해당 슬롯을 회수하므로 모든 웹캠을 해제합니다. 초기화와 자동 할당은 카메라 선택도 지우므로 이후 카메라를 다시 선택해야 합니다. 웹캠이 게시되는 동안 브라우저 탭을 열어 두어야 합니다. 탭이 Insight로 비디오를 보내는 구성 요소이기 때문입니다. 같은 이유로 Insight를 다시 시작해도 웹캠 소스는 `Live`로 복원되지 않습니다. 카메라를 다시 선택하고 시작하세요.

웹캠 시작에 실패하면 메시지에 원인이 표시됩니다:

| 표시되는 메시지 | 조치 |
| --- | --- |
| 카메라 권한이 거부됨 | 브라우저 설정에서 Insight 사이트의 카메라 접근을 허용한 뒤 Media Sources → 로컬 카메라에서 카메라 접근을 다시 활성화합니다. |
| 해당 카메라를 더 이상 사용할 수 없음 | 카메라가 분리되었습니다. **카메라 새로 고침**을 선택하고 다시 선택합니다. |
| 카메라를 시작할 수 없음 | 다른 애플리케이션이 카메라를 사용 중입니다. 해당 애플리케이션을 닫고 다시 시도합니다. |
| 웹캠 게시 엔드포인트에 연결할 수 없음 | 브라우저가 게시 리스너에 연결할 수 없습니다. `webrtcWhip` 엔드포인트의 인증서를 신뢰하도록 설정하고(URL을 한 번 열어 승인), 포트에 접근할 수 있는지 확인합니다([포트 및 네트워크 동작](ports-network.md) 참조). |
| 웹캠 게시가 거부됨 | Insight가 스트림을 수락하지 못했습니다. `webrtcWhip` 포트에 접근할 수 있는지([포트 및 네트워크 동작](ports-network.md) 참조), 브라우저가 Insight 인증서를 신뢰하는지 확인합니다. |

브라우저는 안전하다고 판단하는 페이지에서만 카메라 접근을 허용합니다. **카메라 접근 활성화**에 반응이 없으면 먼저 HTTPS로 Insight를 열고 인증서를 신뢰하도록 설정합니다. [설치 및 업그레이드](install-upgrade.md)를 참조하세요.

## 비디오 뷰어

비디오 뷰어는 비디오 전달 장치에서 전송되는 지연 시간이 짧은 WebRTC 스트림을 표시합니다.

채널 `N`의 경우:

```text
video:    UDP 9000 + N
metadata: UDP 9100 + N
```

예를 들어, 채널 `0`은 비디오 UDP `9000` 및 메타데이터 UDP `9100`를 사용하고, 채널 `1`은 비디오 UDP `9001` 및 메타데이터 UDP `9101`를 사용합니다.

송신자가 DevKit 또는 다른 외부 장치에서 실행되는 경우, `neat --json`에서 매핑된 비디오 `videoUDP` 및 메타데이터 `metadataUDP` 호스트 포트 범위를 사용합니다. 채널 계산은 동일하지만 시작 포트는 다를 수 있습니다.

뷰어는 객체 감지, 분류, 자세 추정, 분할 및 추적을 포함한 일반적인 비전 출력에 대한 메타데이터 오버레이를 렌더링할 수 있습니다. 뷰어 설정을 통해 신뢰도 임계값, ROI 표시, 추적 기록 및 동기화 버퍼링과 같은 오버레이 동작을 조정할 수 있습니다. 메타데이터 타임스탬프는 소스 PTS 밀리초를 사용하며, 사용할 수 없는 경우 생략됩니다.

비디오 뷰어를 사용하여 확인하십시오.

- 애플리케이션이 예상된 채널로 비디오를 전송하고 있습니다.
- 메타데이터가 해당 메타데이터 채널을 통해 전송되고 있습니다.
- 오버레이가 비디오 프레임과 정렬됩니다.
- 브라우저에서 재생이 원활하게 이루어집니다.

![ Insight 비디오 뷰어는 4개의 채널을 표시하는 WebRTC 그리드를 보여줍니다.](../../images/insight-video-viewer.png)

비디오 뷰어는 한 번에 하나 이상의 채널을 표시할 수 있으며, 더 많은 멀티 스트림 테스트를 위해 페이지 매김 및 채널 선택 컨트롤을 제공합니다.

## 주변 장치

주변 장치는 보드에 연결된 카메라와 각 카메라가 보고하는 모드를 표시합니다. 카메라는 보드의 SiMa Sentinel이 검색하고, Insight는 Sentinel의 카탈로그를 읽습니다. 검색은 장치 정보만 읽고 카메라를 열거나 스트리밍하지 않으므로 카메라는 애플리케이션에서 계속 사용할 수 있습니다. 카메라 내보내기 API는 보드에 접근하지 않고 마지막 스캔으로 동작합니다.

### 선택한 보드

Insight는 헤더에 표시된 하나의 선택된 보드로 작업합니다. 이를 선택하면 보드 설정이 열리며 보드를 변경하거나, 연결을 테스트하거나, 다시 플래시된 보드의 호스트 키를 신뢰할 수 있습니다. 주변 장치와 통계 뷰는 이 선택을 사용합니다.

보드는 다음 순서로 선택됩니다.

- **직접 입력한 보드**: 보드 설정을 열고 주소, SSH 포트 및 사용자를 입력합니다. **기본값 사용**을 선택하면 자동 선택으로 돌아갑니다.
- **보드에 설치된 Insight**: Insight가 실행 중인 보드를 검사합니다.
- **Neat SDK**: `sima-cli sdk setup --devkit <ip>`로 페어링된 DevKit입니다.

Insight는 실행 계정의 키로 SSH에 연결합니다. 비밀번호를 요청하거나 저장하지 않습니다. 인증에 실패하면 페이지에 보드에서 키를 승인하는 `ssh-copy-id` 명령이 표시됩니다. 보드를 다시 플래시하면 새 SSH 호스트 키가 제시됩니다. Insight는 지문을 비교하고 **새 키 신뢰**를 선택할 때까지 연결을 거부합니다.

### 카메라 및 모드

**새로 고침**을 선택하여 보드를 스캔합니다. Insight는 SiMa Sentinel에 다시 스캔하도록 요청하고 결과를 기다립니다. Sentinel은 미디어 그래프와 ISP를 통해 MIPI 카메라를, V4L2를 통해 USB 카메라를 찾습니다. Sentinel이 설치되어 있지 않거나, 실행 중이 아니거나, 주변 장치를 보고하기에는 너무 오래된 경우 페이지에 그 내용이 표시됩니다. `sima-cli neat install sentinel`로 설치하거나 업데이트하세요. 각 카메라의 ID, 연결, 장치 식별자, 사용 가능 여부와 카메라가 보고하는 픽셀 형식, 해상도 및 프레임 속도를 표시합니다. 각 카메라와 모드에는 지원 수준이 있습니다.

| 수준 | 의미 |
| --- | --- |
| 검증됨 | 보드의 Neat Core 지원 규칙이 이 모드를 Core `CameraInput`에서 사용할 수 있다고 판단합니다. |
| 지원되지 않음 | Neat Core 규칙이 이 모드를 거부합니다. 예를 들어 USB 카메라와 NV12 이외의 형식입니다. 페이지에는 Sentinel이 보고한 이유가 표시됩니다. 보드에 Neat Core가 없으면 어떤 모드도 지원되지 않습니다. |

Sentinel은 Neat Core가 보드에 설치하는 지원 규칙을 적용합니다. 사용 가능 여부는 Insight가 판단합니다. 새로 고침 중에 각 카메라의 장치 노드를 점유한 프로세스를 확인하고, 카메라를 점유한 프로세스를 표시합니다. Insight는 root로 실행되거나 보드가 비밀번호 없는 `sudo`를 허용할 때만 다른 사용자의 프로세스를 볼 수 있으며, 그렇지 않으면 **알 수 없음**으로 보고합니다.

### 카메라 구성 API

모드 메뉴 아래에서 형식을 고르고 **Copy configuration**을 선택하면 선택한 모드의 내보내기(아래 설명)가 클립보드에 복사됩니다. MIPI 카메라의 경우 선택한 모드를 Neat Core가 검증하지 않았다면 버튼이 비활성화되며, 그 이유가 도구 설명에 표시됩니다. API 클라이언트는 선택한 모드를 `/api/peripherals/cameras/export`에 POST하고 Python(`pyneat.CameraInputOptions`), C++ 및 JSON 표현을 받을 수 있습니다. Insight는 보드의 `libcamerasrc`를 읽지 않으므로 내보내기는 캡처 버퍼 수를 설정하지 않으며 Apps `config.yaml`의 `camera:` 블록을 포함하지 않습니다. 내보내기에는 항상 카메라 이름이 명시됩니다. USB 카메라의 경우 API는 `CameraInput` 구성이 아니라 장치 설명자를 반환합니다.

Modalix DevKit에서 측정된 두 가지 동작이 내보내기에 반영됩니다. 엄격한 제로 카피로 시작되지 않았기 때문에 CPU 폴백(`allow_cpu_fallback = True`)을 허용합니다. 또한 카메라는 요청한 속도가 아니라 libcamera가 선택한 센서 모드의 프레임 속도로 전달합니다. 1920×1080의 IMX477은 15 또는 30 fps를 요청했을 때 약 66 fps를 전달했습니다. 더 적은 프레임이 필요하면 애플리케이션에서 프레임을 삭제하십시오.

## 통계

통계는 `simaai-sentinel` 데몬인 Sentinel에서 보드 자체의 텔레메트리를 읽으므로 애플리케이션 동작과 장치 동작을 구분할 수 있습니다. 프레임 드롭은 스트림 경로에서 발생할 수도 있지만 보드 전력, 온다이 온도, CPU 부하 또는 메모리 압박과 상관관계가 있을 수도 있습니다.

통계는 주변 장치 페이지와 동일한 **보드** 패널에서 선택한 보드를 대상으로 작동합니다.

### Sentinel 데몬

페이지는 먼저 해당 보드에 Sentinel이 설치되어 실행 중인지와 그 버전을 표시합니다. Sentinel이 없으면 **Sentinel 설치**를 선택합니다. Insight는 보드 자체에서 `sima-cli neat install sentinel`을 실행하며, 이를 위해서는 보드에 `sima-cli`가 있고 암호 없는 `sudo`를 사용할 수 있어야 합니다. 둘 중 하나라도 없으면 페이지는 대신 보드의 셸에서 실행할 명령을 알려 줍니다. 설치되어 실행 중인 데몬은 여기에서 다시 설치되지 않습니다. 설치 프로그램이 데몬을 다시 시작하여 진행 중인 트레이스를 끝내 버리기 때문입니다.

거부되거나 실패한 설치는 읽기 실패가 아니라 설치로 보고됩니다. 페이지는 설치가 이루어지지 않았음을 알리고, 그 이유를 보드 자체의 문장으로 제시하며(`sima-cli` 없음, 암호 없는 `sudo` 없음, 0이 아닌 코드로 종료된 설치 프로그램, 또는 완료되었지만 서비스가 여전히 중지된 설치 프로그램), 설치 프로그램의 출력은 **설치 프로그램 출력** 아래에 보관합니다.

### 실시간 지표

DevKit 보기는 Sentinel 자체의 터미널 대시보드(`simaai-sentinel ops`)와 같은 배치로 구성되어 있습니다. 상태 줄에는 판독값이 실시간인지 여부와 현재 Sentinel 세션이 시작된 시각이 표시되며, 세션 평균과 최댓값은 이 세션을 대상으로 합니다. **CSV 내보내기**는 Sentinel이 세션 동안 보유한 각 샘플 시점의 모든 지표를 다운로드하며(최근 240개, 약 8분. 더 오래 기록하려면 **실행 기록**에서 트레이스를 기록하십시오), **업데이트 일시 중지**는 폴링을 중지합니다. 그 아래에는 6개의 탭이 있습니다.

- **개요**: 가장 뜨거운 온도 센서, 보드 전력, CPU 사용량, Linux 메모리, MLA 메모리, 네트워크 트래픽 차트를 표시하며, 그 아래에 **모든 지표**가 접혀 있어 모든 지표를 Sentinel의 순서대로 보여 줍니다.
- **온도**: 시간에 따른 가장 뜨거운 센서와, 각 센서 그룹(MLA, APU, CVU, TOP, Board)의 작은 차트.
- **전력**: 현재, 세션 평균, 세션 최대 전력을 수치로 표시하고, 기간 동안의 보드 전력을 세션 평균을 표시하여 보여 주며, 위쪽 가장자리가 보드 전체 전력이 되도록 전원 레일을 쌓아서 보여 줍니다.
- **시스템**: **CPU 및 메모리**는 CPU 사용량, 부하 평균, Linux 메모리, MLA 메모리, EV74 CMA 사용량을 차트로 표시합니다. **코어별 CPU**는 부하 히트맵으로, 코어마다 한 행, 기간의 10초마다 한 열을 단일 파란색으로 표시하며 각 코어의 1분 평균과 가장 바쁜 코어를 함께 보여 줍니다. 평균이 코어의 한계를 넘으면 주황색 또는 빨간색으로 바뀝니다.
- **스토리지 및 네트워크**: eMMC 사용량, 네트워크 수신 및 송신, eMMC 읽기 및 쓰기와 해당 지표.
- **실행 기록**: 트레이스를 기록하고, 저장된 실행 기록을 열거나 비교하거나 삭제합니다. 비교는 선택한 모든 실행 기록에 대해 하나의 계열(총 전력, 온도 최댓값, CPU, 부하, RAM, MLA 메모리 또는 EV74 CMA)을 모든 실행 기록이 공통으로 포함하는 시간 범위에서 실행 기록에 맞춘 축척으로 겹쳐 표시하며, 각 실행 기록의 최솟값, 평균, 중앙값, P95, 최댓값, 기준선 대비 변화, 에너지를 함께 보여 줍니다. 지표별 비교는 그 아래에 접혀 있습니다.

차트는 고정 축척(백분율은 0-100, 온도는 40-90 °C, 그 밖의 값은 최댓값보다 큰 어림수까지)을 사용하고, Sentinel이 정의한 경고 및 위험 수준을 표시하며, 마우스를 올리면 해당 지점의 모든 계열 값을 보여 줍니다. 색상은 상태를 의미합니다. 차트는 판독값이 경고 또는 위험 수준을 넘을 때까지 파란색이며, 넘으면 주황색 또는 빨간색이 됩니다. 탭 안의 지표가 임계값을 넘으면 탭 이름에 표시가 붙습니다. 보드가 측정할 수 없는 지표는 0이 아니라 엠 대시로 표시됩니다.

차트는 Sentinel이 보관하는 전체 기간인 240개 샘플(약 8분)을 다룹니다. 보드를 처음 읽을 때와 1분 넘게 폴링이 멈춘 뒤에는 Insight가 Sentinel 자체 캐시에서 샘플을 가져오고, 이후 탭이 열려 있고 보이는 동안 2초마다 샘플을 추가합니다. 브라우저 탭이 숨겨지거나 보기를 벗어나도 폴링이 중지됩니다.

보고 있는 동안 보드가 응답을 멈추면 폴링은 중지되지만, 페이지를 비우지 않고 패널이 그대로 남아 마지막으로 읽은 값과 무엇이 실패했는지에 대한 보드 자체의 설명을 유지합니다. 다른 보드를 선택하는 것은 이와 다릅니다. 이 경우 먼저 모든 내용을 지우므로, 한 보드의 수치가 다른 보드의 이름 아래에 표시되는 일은 없습니다.

### 트레이스와 실행 기록

트레이스는 워크로드 동안의 모든 샘플을 기록합니다. 이름을 지정하고, 필요하면 메모와 태그를 추가한 다음 **트레이스 시작**을 선택합니다. **트레이스 중지**는 트레이스를 보드에 실행 기록으로 저장합니다. Sentinel은 한 번에 하나의 트레이스만 기록하며, 저장된 실행 기록이 이미 사용하는 이름은 거부합니다. 저장된 실행 기록은 상태, 시작 시각, 지속 시간, Sentinel이 해당 실행 동안 측정한 에너지, 샘플 수와 함께 나열되며, 데몬을 다시 시작해도 유지됩니다. 실행 기록을 열면 요약이 표시됩니다. 기록된 모든 지표에 대해 당시 적용된 레이블, 단위, 그룹, 임계값과 해당 실행 기록 샘플 전체의 최솟값, 최댓값, 평균값이 표시됩니다. 실행 중 어느 시점에서든 경고 또는 위험 임계값을 넘은 지표에는 표시가 붙습니다. 샘플을 하나만 포착한 실행 기록은 그 시점에서 그 시점 자신까지의 범위가 아니라 샘플을 수집한 순간으로 보고되며, 평균값, 최솟값, 최댓값은 모두 같은 단일 값으로 표시됩니다. 실행 기록의 메타데이터(이름, 메모, 샘플 간격, Sentinel 버전, 실행된 보드)는 그 아래에 있습니다.

실행 기록을 체크하면 선택한 개수와 수행할 수 있는 작업을 보여 주는 도구 모음이 나타납니다. 2개에서 8개를 선택하고 **비교**를 누르면 지표가 행에, 실행 기록이 열에 배치됩니다. Sentinel은 하나의 기준선 실행 기록을 기준으로 비교를 측정하며, 기준선 실행 기록은 각 실행 기록의 메모와 함께 헤더에 표시됩니다. 그 밖의 모든 셀에는 해당 실행 기록에서 그 지표의 평균값과, 그 옆에 기준선 대비 백분율 변화가 표시됩니다. 표시하기에 너무 작은 변화는 변화 없음이 아니라 “<0.01%”로 표시됩니다.

셀에 변화 대신 “—”가 표시되면 Sentinel이 변화를 제공하지 않은 것이며, 표는 엠 대시 하나로 모든 이유를 대신하지 않고 어떤 이유에 해당하는지 알려 줍니다. “—”에 마우스를 올리거나, Tab 키로 이동하거나, 탭하면 옆에 이유가 표시되며, 화면 판독기는 대시와 함께 이유를 읽어 줍니다. 이유는 다음과 같습니다.

- **Sentinel이 이 항목의 변화를 게시하지 않습니다.** 실행 합계(지속 시간, 에너지, 샘플 수)는 백분율 없이 실행 기록별로 보고됩니다.
- **기준선의 측정값이 0이며, 0에서의 백분율 변화는 없습니다.** 기준선은 해당 지표를 측정했지만, 0에서의 백분율이 존재하지 않을 뿐입니다. 이는 유휴 상태 기준선의 코어별 CPU 사용량에서 흔하며, 변화가 가장 큰 경우가 많은 곳이기도 합니다. 기준선에서 평균 0%, 다른 실행 기록에서 5.9%였던 코어는 여기에서 “—”로 표시되므로, 변화가 아니라 두 값을 읽으십시오.
- **기준선 실행 기록에 해당 지표의 값이 없습니다.** 기준선이 그 지표를 전혀 측정하지 않은 유일한 경우입니다.
- **이 실행 기록에 해당 지표의 값이 없습니다.** 실행 기록이 목록에 있지만 Sentinel이 그에 대해 아무것도 요약하지 않은 경우, 열 전체가 이렇게 표시되며 표 위에 따로 안내됩니다.

실행 합계는 보기의 나머지 부분과 같은 단위로 표시됩니다. Sentinel이 밀리초로 보고하는 지속 시간은 초로, 에너지는 줄로 표시됩니다.

선택된 실행 기록이 보드에서 삭제되면 해당 행이 목록에서 사라져 선택을 해제할 체크박스도 없어지므로, 모든 비교가 그 실행 기록 때문에 실패합니다. Insight는 Sentinel이 더 이상 나열하지 않는 선택된 실행 기록의 이름을 알려 주고 선택에서 제외하도록 제안합니다.

비교는 실행 기록을 쉼표로 구분된 하나의 이름 목록으로 요청하므로 트레이스 이름에는 쉼표를 포함할 수 없습니다. 쉼표가 있으면 요청이 보드에 없는 두 개의 실행 기록으로 해석되어, 아무도 선택하지 않은 실행 기록의 이름을 언급하며 실패합니다. Insight는 트레이스를 시작할 때 그런 이름을 거부하고, 이미 저장된 실행 기록에 그런 이름이 있으면 비교가 그 때문에 실패하도록 두지 않고 해당 실행 기록의 이름을 알려 줍니다.

### 떠난 보드의 값

보드를 읽으려면 SSH 왕복이 필요하므로 다른 보드를 선택한 뒤에 응답이 도착할 수 있습니다. 다른 보드를 선택하면 이전 보드에서 아직 오고 있는 모든 것이 취소됩니다. 새 보드는 즉시 확인되며, 이전 보드에서 늦게 도착한 응답은 새 보드의 값으로 표시되지 않고 버려집니다. **트레이스 중지**는 해당 트레이스를 읽어 온 보드의 이름을 표시하며, 다른 보드의 트레이스를 중지하는 대신 거부됩니다. 선택된 보드가 다른 곳(다른 브라우저 탭이나 API 클라이언트)에서 변경되면, 페이지에 이미 있는 값에 그 값을 가져온 보드가 레이블로 표시되고 다시 읽을 수 있는 방법이 제공됩니다.

### Insight 호스트

실행 기록 아래의 간결한 패널은 Insight 자체가 실행되는 머신(SDK 컨테이너 또는 Insight가 설치된 보드)에 대해 `/api/metrics`에서 CPU 부하, 메모리, 디스크, 그리고 플랫폼이 제공하는 경우 온도를 보고합니다. 이 패널은 컨테이너의 디스크가 부족해지고 있는지와 같이 위의 보드 텔레메트리와는 다른 질문에 답하며, 2초가 아니라 15초마다 읽힙니다. 레거시 `REMOTE_DEVKIT` 구성이 설정된 경우 이 패널은 대신 해당 연결을 보고하고 그 사실을 표시합니다. 엔드포인트가 판독값을 전혀 반환하지 않으면 패널은 레이블을 엠 대시와 함께 나열하지 않고 그 사실을 표시합니다.

### NEAT 프로파일링 타임라인

탭의 마지막에 있는 프로파일링 타임라인은 실행 중인 애플리케이션에서 Insight가 스트리밍하는 프로파일링 이벤트의 숫자 필드를 그래프로 표시합니다. 이는 Sentinel과 독립적이며, 장치가 아니라 애플리케이션을 측정합니다.

## 시스템 정보

시스템 정보 패널은 Insight가 확인할 수 있는 환경을 요약하여 보여줍니다. Neat 개발 환경에서는 SDK 및 구성 요소 정보, Insight 상태, 업데이트 정보, 그리고 `mainUI` 및 `videoUI`와 같은 노출된 포트 매핑을 표시할 수 있습니다.

URL이 기본 포트와 일치하지 않을 때 가장 먼저 확인해야 하는 곳입니다. Insight는 사용 가능한 포트 맵을 읽고 뷰어를 열 때 매핑된 `videoUI` 포트를 사용합니다. 명령줄 워크플로의 경우, `neat --json`은 동일한 포트 맵 정보를 표시합니다.
