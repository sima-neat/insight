# Довідник із REST API

Insight надає площину керування, якою користується браузер, як HTTP API. За його допомогою можна автоматизувати перевірки стану, імпорт медіа, налаштування потокових джерел, виявлення переглядача, огляд робочого простору та діагностику середовища виконання.

Запущена служба публікує дві кінцеві точки документації API:

- `GET /api/docs` відкриває інтерактивний інтерфейс Swagger UI.
- `GET /api/openapi.json` повертає документ OpenAPI 3.1 для генерації клієнтів та інших інструментів.

Для типової локальної інсталяції відкрийте:

```text
https://127.0.0.1:9900/api/docs
```

Insight зазвичай використовує локально згенерований сертифікат для розробки. Клієнтам командного рядка може знадобитися довіряти цьому сертифікату або використовувати `-k` для локальної діагностики:

```bash
curl -k https://127.0.0.1:9900/api/health
curl -k https://127.0.0.1:9900/api/openapi.json -o neat-insight-openapi.json
```

## Типовий сценарій автоматизації

Завантажте файл, призначте його слоту джерела та запустіть відтворення:

```bash
curl -k -F "file=@person_clip.mp4" \
  https://<INSIGHT_HOST>:9900/api/upload/media

curl -k -H "Content-Type: application/json" \
  -d '{"index":1,"file":"person_clip.mp4"}' \
  https://<INSIGHT_HOST>:9900/api/mediasrc/assign

curl -k -H "Content-Type: application/json" \
  -d '{"index":1}' \
  https://<INSIGHT_HOST>:9900/api/mediasrc/start
```

Перш ніж змінювати призначення або стан відтворення, прочитайте `/api/mediasrc`. За можливості зупиняйте активні джерела, перш ніж видаляти їхні медіафайли.

## Правила відповідей і потокової передачі

- Більшість кінцевих точок повертають JSON. Для помилок зазвичай використовується `{"error": "message"}` разом із кодом помилки HTTP.
- Завантаження та імпорт повертають потоковий перебіг виконання у форматі `text/plain`, а не один об’єкт JSON.
- `/api/neat-metrics` — це потік подій, що надсилаються сервером (server-sent events).
- Кінцеві точки попереднього перегляду MJPEG і джерел повертають багатокомпонентні (multipart) потоки зображень.
- Кінцеві точки необроблених файлів медіа та робочого простору повертають запитаний двійковий вміст.

Інтерфейс Swagger UI використовує той самий хост, що й Insight, тому його запити **Try it out** (Спробувати) спрямовуються на поточну інсталяцію. Такі операції, як видалення, скидання, запуск і зупинка, негайно змінюють стан служби.

## Групи API

Документ OpenAPI групує операції за призначенням:

- **Service and system** (служба та система) — стан, середовище, відомості про збірку, метрики, журнали та додаткові інструменти.
- **Diagnostics** (діагностика) — прийом RTP, вихідний потік WebRTC і метрики, що надсилаються сервером.
- **Media library and imports** (медіатека та імпорт) — каталог, YouTube, завантаження, видалення, перевірка, попередній перегляд і звантаження.
- **Media sources** (джерела медіа) — призначення та керування відтворенням RTSP/HTTP.
- **Viewer** (переглядач) — URL переглядача, доступний із браузера, і налаштована кількість каналів.
- **Workspace** (робочий простір) — перегляд, пошук, огляд і попередній перегляд файлів робочого простору та елементів архівів MPK.
- **DevKit shell** (оболонка DevKit) — виявлення й запуск розміщеного мосту оболонки, якщо його налаштовано.
- **Board** (плата) — вибір плати, яку використовують функції для роботи з платою, перевірка з’єднання SSH і довіра до ключа хоста перепрошитої плати.
- **Peripherals** (периферійні пристрої) — перелік камер MIPI та USB і мікрофонів ALSA, про які повідомляє SiMa Sentinel на вибраній платі, та перевірка мікрофона через API.

Необроблений файл OpenAPI також підтримується в репозиторії Insight за шляхом `neat_insight/openapi.json`. Тести порівнюють його операції із зареєстрованими у Flask маршрутами `/api`, тож нові кінцеві точки не можна додати непомітно, не оновивши довідник.
