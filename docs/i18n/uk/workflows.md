# Типові робочі процеси

<a id="import-standard-test-videos"></a>

## Імпортуйте стандартні тестові відеофайли.

Використовуйте стандартні набори відеоматеріалів, коли вам потрібні повторювані медіафайли для демонстрацій, тестування або перевірки багатопотоковості:

```text
https://artifacts.sima-neat.com/assets/videos/720p16/video01.mp4
...
https://artifacts.sima-neat.com/assets/videos/720p16/video16.mp4

https://artifacts.sima-neat.com/assets/videos/480p30/video01.mp4
...
https://artifacts.sima-neat.com/assets/videos/480p30/video16.mp4
```

Для ручного використання завантажте необхідні файли та завантажте їх із джерела медіа.

Для налаштування через API перевірте, чи вже є в Insight файли медіа:

```bash
curl -k https://127.0.0.1:9900/api/media-files
```

Якщо медіатека порожня, завантажте та додайте стандартне відео:

```bash
tmpdir="$(mktemp -d)"
curl -fL "https://artifacts.sima-neat.com/assets/videos/480p30/video01.mp4" \
  -o "${tmpdir}/video01.mp4"
curl -k -F "file=@${tmpdir}/video01.mp4" \
  https://127.0.0.1:9900/api/upload/media
```

Повторіть цю процедуру для інших файлів або завантажте архів, якщо ви хочете додати велику кількість медіафайлів.

## Перевірте роботу застосунку, який обробляє відеопотік з однієї камери.

1. Відкрийте Insight.
2. Перейдіть до розділу «Джерела медіа» та завантажте короткий тестовий відеофайл.
3. Перейдіть до розділу «Джерела потокового відео» та призначте відео для `src1`.
4. Почніть `src1`.
5. Запустіть свою програму, використовуючи правильне RTSP URL-адресу:
   - Усередині контейнера SDK: `rtsp://127.0.0.1:8554/src1`
   - На пристрої DevKit або на зовнішньому комп’ютері: `rtsp://<sdk-host-ip>:<rtsp.tcp hostPortStart>/src1`
6. Відкрийте програму для перегляду відео та перегляньте канал `0`.
7. Якщо ваш додаток надсилає метадані, переконайтеся, що відповідні елементи відображаються на відео.
8. Використовуйте заповнювач «Статистика», щоб дізнатися, де в наступній версії відображатимуться дані системної діагностики навантаження.

## Перевіряйте декілька потоків вхідних даних.

1. Завантажте або підготуйте кілька відео у розділі «Джерела медіа».
2. Використовуйте потокові джерела. `Auto Assign` щоб зіставити відео з відповідними слотами джерела.
3. Використовуйте `Bulk Start`, щоб вказати кількість джерел, які очікує ваш додаток.
4. Запустіть програму, використовуючи відповідні URL-адреси потоків `srcN`.
5. Відкрийте програму для перегляду відео, налаштувавши потрібний канал.
6. Використовуйте інструменти діагностики для перегляду, щоб виявити вузькі місця в потоці даних. У цій версії розділ «Статистика» є лише тимчасовим, і в наступній версії планується додати інструменти діагностики вузьких місць у середовищі виконання.

Коли програма запускається поза контейнером SDK, перед запуском тесту визначте та налаштуйте хост-порти для RTSP, відеопотоку UDP та метаданих UDP, використовуючи дані з `neat --json`.

## Налаштуйте кінцеві точки застосунку на основі відображення портів SDK.

Використовуйте цей процес, коли програма працює на DevKit, а Insight працює всередині SDK:

1. В SDK перевірте, чи запущено Insight:

   ```bash
   insight-admin status
   ```

2. Отримайте карту портів SDK:

   ```bash
   neat --json
   ```

3. Знайдіть IP-адресу хоста SDK за посиланням `insight.webUiUrl`, або скористайтеся IP-адресою хоста, яка відображається під час процесу налаштування SDK.
4. Знайдіть `rtsp.tcp.hostPortStart`, `videoUDP.hostPortStart` та `metadataUDP.hostPortStart` у `exposedPorts`.
5. Налаштуйте потоки вхідних даних програми за допомогою:

   ```text
   rtsp://<sdk-host-ip>:<rtsp.tcp hostPortStart>/src1
   rtsp://<sdk-host-ip>:<rtsp.tcp hostPortStart>/src2
   ```

6. Налаштуйте вихідні порти програми для кожного каналу:

   ```text
   video channel N:    <sdk-host-ip>:<videoUDP hostPortStart + N>
   metadata channel N: <sdk-host-ip>:<metadataUDP hostPortStart + N>
   ```

7. Запустіть програму та відкрийте переглядач відео.
8. Використовуйте `/api/ingest/stats`, якщо у користувача не відображається відео. Ця функція повідомляє, чи надходять дані RTP і метадані до Insight перед тим, як ви почнете налагоджувати роботу браузера або WebRTC.

## Виправлення проблем із відсутнім відео або накладками.

Використовуйте цю послідовність дій, щоб визначити причину проблеми:

1. Переконайтеся, що програма запущена та націлена на правильний хост Insight.
2. Підтвердіть, чи запущено програму всередині контейнера SDK, чи на зовнішньому пристрої.
3. Якщо це зовнішній ресурс, переконайтеся, що він використовує відображені хост-порти `videoUDP` і `metadataUDP` з `neat --json`.
4. Якщо він знаходиться всередині контейнера SDK, переконайтеся, що вихідний відеопорт знаходиться в `9000-9079`.
5. Переконайтеся, що метадані-порт, якщо він використовується, відповідає каналу в діапазоні метаданих UDP.
6. Відкрийте програму для перегляду відео та перевірте, чи відображається потрібний канал.
7. Використовуйте системну інформацію, щоб перевірити, чи використовує Insight стандартні порти чи порти, визначені в SDK.
8. Використовуйте «Системну інформацію» та журнали для перевірки стану пристрою. Наразі розділ «Статистика» є лише тимчасовим і в наступній версії планується доповнити його інформацією про завантаження пристрою та стан його роботи в середовищі виконання.

Якщо відео відображається, але відсутні накладені елементи, зверніть увагу на шлях до метаданих. Якщо накладені елементи відображаються із затримкою або не синхронізовані, відрегулюйте налаштування затримки метаданих у програмі перегляду.

## Поради

- Використовуйте короткі відео- та аудіофрагменти під час створення нового циклу в застосунку. Це прискорить налаштування вихідних даних і повторну перевірку.
- Використовуйте джерела HTTP MJPEG, коли вам потрібно імітувати камеру, яка передає багатокомпонентний MJPEG через HTTP.
- Забезпечте послідовність нумерації каналів: якщо відео надходить на канал `N`, надсилайте метадані до порту метаданих для того ж `N`.
- Використовуйте перегляд «Робочий простір», щоб переглянути створену модель і артефакти профілювання перед копіюванням файлів із середовища.
- Використовуйте функцію «Швидкий огляд», розташовану у верхньому правому куті інтерфейсу Insight, коли ви знайомите нового розробника з інструментом.
- Перш ніж припускати, що вказано неправильний номер порту, перевірте системну інформацію. У разі розгортання SDK, номер порту, який використовується для взаємодії з браузером, може відрізнятися від внутрішнього номера порту служби.
